# 跨目录自动云端访问

已连接公司 WireGuard 的同一台电脑，可以在安装版、desktop:dev 和 desktop:preview 中自动获取已发布模型，并打开获准的 ERP 和管理后台。每个目录无需重新导入设备文件。公司云端分别展示自动识别、模型同步及本目录接入配置。

自动识别不代表本目录已安装隧道、已激活或已启用上传。管理员角色、ERP 入口与 erp_actions 仍由服务器逐次检查；获取模型不会授予管理员角色。

## 缓存与状态

启动、约每 60 秒、恢复唤醒和手动刷新时重新验证。没有个人模型凭据时采用云端默认模型；个人模型配置和选择保留。

模型缓存使用每个目录原有的系统加密存储，记录服务器、设备类型、设备 ID 和 WireGuard 地址。目录之间不复制聊天、工作区、密钥或设置。

- 暂时断网保留缓存并显示最近验证时间，离线不能申请新网页会话。
- 模型下架、凭据版本改变、明确拒绝设备后清理相应缓存并更新后续请求。
- 设备变化先清理旧缓存并等待确认；与已有接入配置冲突时，需处理原配置。
- 清除本目录模型缓存不撤销设备权限；保持公司连接时，下次刷新会重新获取。
- 旧缓存仅在接入配置能确定归属时迁移，否则清除后重新领取，个人模型凭据保留。

## 接口约定

原 /api/v1/device-context 保持只返回权限，不含密钥。新接口由桌面主进程直接访问：

| 接口 | 用途 |
| --- | --- |
| GET /api/v1/device-access | 设备、管理员角色及版本、已发布模型目录 |
| GET /api/v1/device-access/llm-credential | 按 provider、model、model_schema 领取模型凭据 |
| POST /api/v1/device-access/browser-handoff | 按 target=admin/erp 领取网页登录交接码 |

新请求不带旧身份凭据和 Cookie，不使用系统或 Clash 代理，不跟随重定向。固定原生请求头不是秘密；服务器以实际 WireGuard 来源唯一识别设备。目录、模型凭据及交接码响应中的设备身份必须一致。密钥不经过 CLI 标准输出或 Renderer。

网页登录继续兑换一次性交接码并使用原 Cookie 路径、同源和 CSRF 校验。交接码 60 秒，会话最长 8 小时、空闲 30 分钟过期。新会话明确记为 WireGuard 来源，每次使用重新检查设备与权限，不修改机器绑定。

新接口缺失会提示升级服务器，不回退旧凭据认证。旧 Agent 仍使用原接口。设备激活、迁移和隧道维护保留；旧身份检查不再更新新版 Agent 的模型状态。

模型仍下发供应商 API Key。停用设备只能阻止再次领取，不能保证供应商立即停止接受已下发 Key；已发出的模型请求也不会被撤回。

## 验证与上线

运行 bun scripts/native-cloud-acceptance.ts，使用临时目录、实际受管 CLI、原生请求客户端、本地模拟服务和实际 Electron 组件。覆盖三种启动配置、中英文、窄屏、模型选择、网页登录、离线、拒绝和清理再获取。截图默认位于系统临时目录 lxe-native-cloud-acceptance；所有密钥与交接码均为假数据。

定向测试还覆盖两个独立目录、旧缓存迁移、个人设置保留、模型发布变化、身份连续性、迟到响应和旧服务端提示。

上线先执行服务端 Alembic 0039 迁移并更新服务端，再更新 Agent。无需新权限协议，不改变权限模板、设备绑定和管理员角色。本轮不部署、不发布安装包、不修改 Windows 绑定；真实 Windows 联调等待新服务端可用。模拟启动配置不能替代真实 Windows 联调。
