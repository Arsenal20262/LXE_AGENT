# 越南备货来源与运营 SKU 表准备

PR2 在输入资产契约之上提供雅仓来源采集、来源校验、SKU 参数解析及运营回填表准备，不生成最终备货量或五表工作簿。下文单独记录 PR6 的稀疏映射结果和 PR7 新增的聊天绑定入口，不改变 PR2 当时的职责。

当前由 AI 复用 `yacang-reports-export` 获取 VN8806 库存动销、VN8806 当前库存列表和全局仓库产品资料，再通过三份路径调用独立计算。`load_vietnam_files()` 只快照、读取和校验文件；原内部自动导出函数已移除。仓库产品资料按本轮越南 SKU 精确筛选；不重新实现认证或下载。三类导出必须都成功，来源与仓库身份必须正确。本轮 SKU 是动销与当前库存两表的并集。缺一侧来源的 SKU 保留并给出缺项诊断。

总在途以当前库存列表的 `在途数量` 为权威；动销表在途仅用于差异提示，不填补当前库存表空值。仓库产品资料的 `创建时间` 保留为原始数据，后续生成层根据已确认业务口径将它用作真实上架时间。本层不改写导出文件。

`prepare_operator_sku_map(template_path, output_path, current_map_path=None, *, sources)` 是历史模板辅助能力：从本轮 SKU 集合生成运营可填写的映射表和参考页；显式参数可带入，历史模板值只作核对参考，不自动变成运营显式输入。必须显式传入已经读取的 `sources`，没有隐式采集分支。目标路径已存在会拒绝覆盖。

`resolve_sku_parameters()` 提供历史模板参考解析。五表生成由 `generate_vietnam_workbook()` 使用内置骨架和调用方提供的映射表路径；后续 PR4 在线流程从受信 SKU current 提供该路径。生成不从模板历史价格兜底。运营映射表以精确 SKU 为键，空白与显式零不同，不借用相似 SKU。

测试使用合成 XLSX 与 mock；真实模板、雅仓导出和业务价格不得提交 Git。本层不提供聊天或 CLI 一键入口；五表生成由独立的 Workbook 服务提供。

## 稀疏映射的生成结果

生成以本轮动销与当前库存的 SKU 并集为行集合，映射表按精确 SKU 左连接。没有映射行时只留空热销、成本、价格、备货天数、备货量和财务列。已有映射行须完整：三个金额大于零，热销标记为 `1` 或 `2`，否则校验失败。来源表、库存、销量、总在途和不依赖映射的公式继续保留。映射表额外 SKU 不进入结果，但也须填写完整。

## PR7 聊天绑定后的使用口径（历史记录，已替代）

PR2 的 `prepare_operator_sku_map()` 与 `resolve_sku_parameters()` 仍是历史模板辅助能力，当前五表生成不调用它们。PR7 允许业务人员在聊天中上传一张 `.xlsx` SKU 参数表：只要求绑定时只绑定；附表要求生成越南备货时先绑定，再运行在线生成。受控入口先核对本轮唯一附件或符合紧邻规则的上一轮唯一附件，随后 `lxeskill vietnam sku bind` 复验内容并更新受信 current。绑定失败不得沿用旧版生成；没有待处理的新附件时才读取已绑定 current。多附件或单独上传但用途不明时先澄清。工作台保留 current、previous 和回滚展示，不再提供上传按钮。

聊天入口不绕过 PR1 的表头与数值校验、PR5 的受信版本存储，也不改变 PR2 的雅仓来源校验。至少需要一个有效 SKU；可缺少本轮部分 SKU 行，已有行的空价格按 PR6 条件公式留空，显式零仍是已填写的值。真实业务模板、导出和价格不进入 Git 或安装包。
