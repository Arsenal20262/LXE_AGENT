# 越南备货：本轮雅仓数据与运营 SKU 表

本页记录 PR2 已实现的雅仓数据合并和运营表辅助接口；完整五表的当前运行口径见 [PR3 设计](pr3-workbook-design.md)。PR2 的历史模板读取接口仍在代码中，但 PR3 生成不调用它，也不依赖已绑定模板。业务总目标见[最终设计](design.md)。

## 本轮数据范围

`export_vietnam_sources()` 复用现有 `services.yacang.workflow.run`，一次请求 `VN8806` 库存动销、`VN8806` 当前库存列表和全局仓库产品资料。仓库产品资料由雅仓原流程全局导出，读取时按本轮越南 SKU 精确筛选。请求不带库存动销的“创建日期”筛选，以免漏掉旧 SKU。

三份文件必须全部成功且身份正确。本轮 SKU 是越南库存动销与当前库存列表的**并集**；只在其中一份出现的 SKU 仍进入运营表，并标出缺少的实时来源。两份都为空时失败。空白、非文本或重复 SKU，以及保留行中的公式，都不能作为可靠输入。全局商品资料的其他 SKU 不进入本轮结果。

五表计算使用的“总在途”以当前库存列表的 `在途数量` 为准；动销的 `在途` 只做数值差异诊断，不补齐库存列表的空值。商品资料的 `创建时间` 已由业务确认是真实上架时间。PR2 仅保留该原始字段；PR3 按精确 SKU 校验并规范成 `YYYY-MM-DD HH:MM` 文本，缺失或冲突时停止生成。

## 运营上传表

PR2 的 `prepare_operator_sku_map(template_path, output_path, current_map_path=None)` 仍是依赖本地完整模板的**辅助接口**：它先校验模板和已有参数表，再取得本轮雅仓数据，最后生成一个新 XLSX。调用方已经取得同一轮数据时可传 `sources=`，避免再次导出。目标路径若已有文件会报错，不覆盖现有运营表。PR3 完整五表入口直接读取运营已上传的映射表和应用内置骨架，不调用此辅助接口；后续前端入口也不能要求用户上传完整模板。

第一张 `SKU参数映射` 表可由 PR1 的 `load_sku_parameters()` 直接读取。PR2 辅助输出的列为 `SKU`、`成本`、`跨境价`、`折扣价`、`热销标记`、`上架时间`；PR3 要求热销标记表头，但值可空，`上架时间` 是旧版兼容列。新上传表必须为本轮每个 SKU 显式填写成本、跨境价、折扣价；上架时间来自仓库产品，无需运营填写。可编辑值仅从已有运营显式参数表带入；无显式值则留空，显式零仍为零。

PR2 辅助输出的第二张 `核对参考` 表展示同 SKU 的模板历史参数、历史冲突或无效原因，以及缺动销、缺库存、缺商品、缺总在途、在途不一致标记。历史值绝不写入第一张表的可编辑单元格。该参考页不属于 PR3 生产输入，也不能让历史值自动成为已确认价格。高精度价格按文本保存以保留精确值，PR1 读取时仍按数值校验。

PR2 的 `resolve_sku_parameters()` 保留旧模板历史分析能力，但 PR3 不用其模板历史兜底。PR3 只取运营显式成本与价格、商品资料创建时间，以及热销显式值或默认 `2`；缺少必需字段就报告 SKU 和字段并停止生成。PR2 参考页中的历史值不会悄悄变成运营显式输入。

## 调用边界与未完成项

当前是 Python 服务接口，尚未注册 Vietnam Skill 或 Desktop 上传入口；这些属于后续独立 PR。真实九表模板、雅仓导出、价格和运营表保持在本地受控目录，不提交 Git，也不随安装包分发；PR3 仅发布从全新工作簿构造、无历史数据的五表骨架。开发验证使用合成 XLSX 和已有雅仓本地模拟测试，没有调用生产雅仓；当前库存列表的真实导出仍需在后续联调时验收。
