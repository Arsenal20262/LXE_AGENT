# 越南备货：本轮雅仓数据与运营 SKU 表

本模块接在[输入资产契约](asset-contract.md)之后，为后续五表计算准备本轮数据和运营可回填的 SKU 参数表。业务总目标见[最终设计](design.md)。这里不生成备货数量或最终五表工作簿。

## 本轮数据范围

`export_vietnam_sources()` 复用现有 `services.yacang.workflow.run`，一次请求 `VN8806` 库存动销、`VN8806` 当前库存列表和全局仓库产品资料。仓库产品资料由雅仓原流程全局导出，读取时按本轮越南 SKU 精确筛选。请求不带库存动销的“创建日期”筛选，以免漏掉旧 SKU。

三份文件必须全部成功且身份正确。本轮 SKU 是越南库存动销与当前库存列表的**并集**；只在其中一份出现的 SKU 仍进入运营表，并标出缺少的实时来源。两份都为空时失败。空白、非文本或重复 SKU，以及保留行中的公式，都不能作为可靠输入。全局商品资料的其他 SKU 不进入本轮结果。

后续计算使用的“总在途”以当前库存列表的 `在途数量` 为准；动销的 `在途` 只做数值差异诊断，不补齐库存列表的空值。这个口径由用户在 PR2 开发时确认。商品资料的 `创建时间` 只保留为原始字段，不作为 `上架时间`。

## 运营上传表

`prepare_operator_sku_map(template_path, output_path, current_map_path=None)` 先校验本地模板和已有参数表，再取得本轮雅仓数据，最后生成一个新 XLSX。调用方已经取得同一轮数据时可传 `sources=`，避免再次导出。目标路径若已有文件会报错，不覆盖现有运营表。

第一张 `SKU参数映射` 表可由 PR1 的 `load_sku_parameters()` 直接读取。行只包含本轮 SKU；列为 `SKU`、`成本`、`跨境价`、`折扣价`、`热销标记`、`上架时间`。这些是三类雅仓数据无法提供、且属于 SKU 级的业务输入。可编辑值仅从已有运营显式参数表带入；无显式值则留空，显式零仍为零。

第二张 `核对参考` 表展示同 SKU 的模板历史参数、历史冲突或无效原因，以及缺动销、缺库存、缺商品、缺总在途、在途不一致标记。历史值绝不写入第一张表的可编辑单元格。即使完整模板已有历史值，也需要运营自己确认后填入第一张表，才能成为新的显式参数。高精度价格按文本保存以保留精确值，PR1 读取时仍按数值校验。

`resolve_sku_parameters()` 为后续计算保留字段来源：运营显式值 > 同 SKU 无冲突的模板字面值 > 已确认的热销默认值 `2` > 缺失。重复历史行的不同非空值、公式或无效值不能作为兜底。这个**计算时的来源优先级**与运营上传表的空白语义分开：默认热销 `2` 和模板历史都不会悄悄变成上传表中的运营显式值。

## 调用边界与未完成项

当前是 Python 服务接口，尚未注册 Vietnam Skill 或 Desktop 上传入口；这些属于后续独立 PR。真实模板、雅仓导出、价格和运营表保持在本地受控目录，不提交 Git，也不随安装包分发。开发验证使用合成 XLSX 和已有雅仓本地模拟测试，没有调用生产雅仓；当前库存列表的真实导出仍需在后续联调时验收。
