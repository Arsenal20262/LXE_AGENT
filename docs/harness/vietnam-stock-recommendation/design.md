# LXE Agent 越南备货功能——最终设计与 Codex 实施规范

> **用途**：本文件作为 `feature-vietnam-stock-recommendation` 越南备货功能重新收敛开发的业务与技术基线。
> **目标**：业务用户最终只需要在 LXE Agent 聊天窗口输入“生成越南备货”等自然语言，即可得到计算完成、格式与业务模板一致、且仅包含本轮越南数据的 XLSX 文件。
> **原则**：优先复用现有 LXE Agent、雅仓导出、Desktop、本地资产槽、XLSX 与 LibreOffice 能力，不重复造轮子，不为越南功能另起一套平行架构。

---

# 1. 最终业务目标

用户输入：

```text
帮我生成越南备货清单
```

系统自动完成：

```text
用户自然语言
    ↓
Agent Runtime
    ↓
vietnam-stock-recommendation Skill
    ↓
获取当前已绑定的业务模板
    ↓
读取本轮越南 VN8806 数据
    ├─ 库存动销
    ├─ 库存列表
    └─ 仓库产品
    ↓
读取当前 SKU 参数映射表（如已绑定）
    ↓
按 SKU 合并业务输入
    ↓
写入模板
    ↓
LibreOffice 重算模板公式
    ↓
校验结果
    ↓
生成仅包含本轮越南 SKU 的最终 XLSX
    ↓
send_files 返回给用户
```

最终交付不是重新发明一套补货算法，而是：

> **把业务现有模板中的规则、格式与实时业务数据自动结合，稳定生成业务可以直接使用的越南备货清单。**

---

# 2. 已确认的核心业务决策

## 2.1 Skill 边界

```text
yacang-export
= 雅仓原始数据查询 / 导出能力

vietnam-stock-recommendation
= 越南备货业务计算能力
```

用户说“导出越南仓库存”走雅仓；用户说“生成越南备货清单 / 根据越南库存销量算补货”走越南备货 Skill。

雅仓 Skill 不实现越南备货公式；越南备货 Skill 复用雅仓已有数据能力。

## 2.2 雅仓实时数据

本轮实时数据来自雅仓 `VN8806`：

```text
1. 库存动销
2. 库存列表
3. 仓库产品
```

禁止在越南模块重新实现雅仓登录、验证码、Token/Session、导出队列和下载逻辑。

## 2.3 在途口径

当前确认：

> **总在途统一使用雅仓最新导出的总在途。**

旧模板中的 9/18 陆运、9/29 陆运、七批历史在途不再作为本轮备货数量的权威输入，也不得覆盖雅仓最新总在途。

## 2.4 热销默认值

当前确认：

```text
热销标记缺失 → 默认 2
```

如果 SKU 参数映射表显式提供热销标记，则映射表值优先。

---

# 3. 完整模板与 SKU 参数映射表

采用：

> **完整模板 + SKU 参数映射表 + 雅仓实时数据**

## 3.1 完整模板

完整模板负责：

```text
公式
版式
工作表结构
字段位置
默认业务结构
历史 SKU 参数兜底
最终输出格式
```

完整模板由管理员 / 交付人员低频维护，普通业务用户不应通过聊天随意切换或修改。

## 3.2 SKU 参数映射表

SKU 参数映射表用于维护：

> **雅仓拿不到、不能由公式计算、但属于 SKU 级业务输入的数据。**

当前明确至少包括：

```text
SKU
成本
跨境价
折扣价
热销标记
```

正式开发时应根据真实模板公式依赖继续审计，如果发现其他字段同时满足：

```text
① 雅仓 / 在途数据源无法提供
② 不能由模板公式自动计算
③ 属于 SKU 级业务输入
```

则可以加入映射表。

禁止把计算结果字段交给运营维护，例如：趋势、调节系数、日均、调节后日均、款内最大日销、综合判定、可售天数、备货天数、最终备货量、毛利润、毛利率等。

---

# 4. SKU 参数映射规则

## 4.1 主键使用 SKU

SKU 参数映射表以 `SKU` 为唯一匹配主键。

禁止默认使用“款号 → 成本/价格”映射，因为真实业务中可能存在同款不同 SKU 的成本、价格不一致。

```text
款号 = 销量聚合 / 整款判断
SKU   = 成本 / 价格 / 业务参数精确匹配
```

## 4.2 字段优先级

同一 SKU 同一字段存在多个来源时：

```text
SKU 参数映射表显式值
>
完整模板中该 SKU 的已有值
>
业务默认值（仅适用于明确有默认规则的字段，如热销=2）
>
缺失
```

## 4.3 缺失处理

要求数据准确，因此：

```text
找不到 → 明确标记缺失
```

禁止：

```text
❌ 根据款号猜
❌ 根据商品名称相似度猜
❌ 根据颜色 / 尺寸猜
❌ 根据 SKU 后缀猜
❌ 借用其他 SKU 成本
❌ 让 LLM 自由推断
```

只有业务后续明确给出确定性映射规则时，才允许新增规则。

---

# 5. 备货核心与完整运营表的区别

如果只计算“应该补多少货”，核心依赖：

```text
SKU
销量
库存
在途
上架 / 商品信息
热销及备货规则
```

成本、跨境价、折扣价不是最终备货数量的必要输入。

但当前产品目标仍希望输出与原业务模板一致的完整 XLSX，因此价格、利润等区域若要求完整填充，就需要对应 SKU 参数来源。

这也是 SKU 参数映射表存在的原因：

> **它不是为了让备货算法才能运行，而是为了补足完整运营表中雅仓无法直接提供的 SKU 级业务输入。**

# 6. 四个可配置参数

当前四个默认值：

```text
30天参数 = 0.8
15天参数 = 0.8
7天参数  = 0
汇率      = 3900
```

统一由 `RecommendationConfig` 管理。

优先级固定为：

```text
本次聊天临时参数
>
Desktop 设置页长期配置
>
模板 / 系统默认值
```

例如用户说“这次汇率用 4000”，只影响本次执行，不自动持久化。

Desktop 在现有“设置 → ERP 账号 → 雅仓”区域增加“越南备货”折叠配置即可，不新建大型管理页。

# 7. 模板与 SKU 映射表的本地绑定

## 7.1 完整模板

设置页支持：

```text
选择完整模板
替换当前模板
```

首次绑定后复制进应用本地资产槽作为 `current template`，跨聊天、重启和正常软件升级继续复用。

普通聊天不能通过任意路径参数切换模板。

## 7.2 SKU 参数映射表

SKU 参数映射表作为独立资产管理，建议独立槽位：

```text
vietnam_replenishment_template
vietnam_sku_parameter_map
```

完整模板与映射表不能混成同一资产类型。

建议权限：

```text
完整模板：管理员 / 交付维护
SKU 参数映射表：允许运营按业务流程更新
```

真正权限边界放在 Desktop Main / 本地资产写入层，不以“隐藏按钮”作为安全边界。

## 7.3 替换规则

任何资产替换：

```text
候选文件
→ 格式校验
→ 内容预检
→ SHA-256
→ 复制
→ 再验证
→ 成功后切换 current
```

失败时旧 `current` 保持不变。

禁止检测到新文件就直接覆盖。

# 8. Excel 公式计算：优先复用 LibreOffice

当前项目已引入 LibreOffice，因此本轮优先验证并采用：

```text
pandas / openpyxl
→ 数据读取、合并、写入、格式处理

LibreOffice Calc
→ 工作簿公式重算

openpyxl
→ 重算结果读取与校验
```

目标是尽可能让业务模板原公式继续作为规则来源，而不是在 Python 中复制第二套公式。

## 8.1 不再优先扩大自研通用 Excel 引擎

如果真实模板在 LibreOffice 下能够稳定重算，则优先使用 LibreOffice，不继续把 FormulaEvaluator 扩成通用 Excel 引擎。

若仓库已有 FormulaPlan / FormulaEvaluator，先只读核查其真实引用和用途；在 LibreOffice 回归验证完成前不得直接删除。

## 8.2 兼容性验证

必须用真实模板验证：

```text
IF / IFS / IFERROR
VLOOKUP
COUNTIF / COUNTIFS
MAXIFS
ROUNDUP / ROUNDDOWN
文本处理
日期
空值
负数
跨 Sheet 引用
错误值
```

不能因为 LibreOffice 能打开 XLSX 就认为结果正确。

如 LibreOffice 与原业务 Excel 结果不一致，必须明确报告，不得为了测试通过偷偷修改业务结果。

# 9. 最终运行链路

```text
① 获取 current 完整模板

② 获取本轮雅仓 VN8806 三类数据

③ 获取 current SKU 参数映射表（如存在）

④ 确定本轮越南 SKU 集合

⑤ 按 SKU 合并：
   - 雅仓实时数据
   - SKU 参数映射表
   - 模板已有 SKU 参数

⑥ 应用字段优先级

⑦ 总在途强制使用雅仓最新总在途

⑧ 热销缺失填默认 2

⑨ 写入完整模板

⑩ 最终只保留本轮越南 SKU

⑪ 保留模板公式、版式、列顺序和目标结构

⑫ LibreOffice headless 重算

⑬ 读取并校验结果

⑭ 生成最终 XLSX

⑮ send_files 一次后结束
```

# 11. 新 SKU 处理

雅仓本轮可能出现模板历史中没有的新 SKU。

规则：

```text
新 SKU 仍必须进入本轮越南清单
```

实时字段从雅仓获取。

业务参数优先查 SKU 参数映射表。

如果映射表也没有：

```text
热销 → 默认 2
其他无默认规则字段 → 标记缺失
```

禁止自动借用其他 SKU 的成本、价格或人工参数。

# 12. 失败原则

以下情况必须明确失败或标缺失：

```text
完整模板不存在 / 损坏
模板结构不符合 Contract
SKU 参数表格式错误
必要 SKU 字段缺失
雅仓来源失败
LibreOffice 重算失败
重算结果无法读取
关键备货字段产生非法结果
```

禁止：

```text
❌ 用旧文件补齐
❌ 用历史输出冒充本轮结果
❌ 静默回退旧算法
❌ 伪造成功 XLSX
```

# 23. 最终设计原则

> **模板管规则和格式。**

> **SKU 映射表管 SKU 级可变业务参数。**

> **雅仓管库存、销量、商品信息和当前总在途等实时数据。**

> **LXE Agent 负责自动合并、计算、校验和交付，不把技术配置负担转嫁给普通业务人员。**
