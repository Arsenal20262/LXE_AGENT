# 越南备货输入资产契约

本页记录 PR1 资产契约及 PR3 对运行口径的调整。业务规则以[最终设计](design.md)和 [PR3 设计](pr3-workbook-design.md)为准；Desktop 上传绑定仍由后续模块实现。

## 已注册的两个本地资产槽

| 槽位 | PR1 原用途 | PR3 完整五表运行要求 |
| --- | --- | --- |
| `vietnam_replenishment_template` | 完整业务模板 | 不读取其 `current`；保留槽位仅为已有接口兼容 |
| `vietnam_sku_parameter_map` | 运营维护的 SKU 级业务参数 | 后续前端接线后必须有已校验的 `current` |

两个槽位在 PR1 均标记为 `desktop` 管理，现有命令上传入口不能更新。PR3 的离线生成接口接收已复制的映射表文件路径和同一轮雅仓数据，不读取模板槽，也不自动绑定用户附件。后续 Desktop 入口负责映射表候选文件校验、哈希与安全替换，再把已校验的当前版传给生成流程。业务人员无需上传完整模板。

## 旧完整模板校验与新内置骨架

`validate_template(path)` 是 PR1 留下的只读校验入口，供旧完整模板辅助接口和维护时审计使用；PR3 不把该模板当作生成输入。它检查以下五张必需表，允许旧模板另有辅助表：

1. `越南备货清单`
2. `雅仓库存`
3. `雅仓动销`
4. `数据更改`
5. `库存商品信息`

校验还检查主表及辅助表的关键表头，以及主表 `AV2:AY2` 对 `数据更改!A2:D2` 的公式引用。真实模板的历史 SKU 可以重复；本模块仅统计非空行，不把历史行直接作为本轮输出。

PR3 的 `resources/skeleton.xlsx` 由全新工作簿构造，只保留已审计的五表表头、样式、公式和四参数默认值，跟随 Python wheel 发布。它不含历史 SKU、成本、价格、图片、批注或超链接。最终文件只保留上述五表和本轮 `VN8806` 雅仓 SKU，不依赖用户电脑残留的旧模板资产。

## SKU 参数表读取

`load_sku_parameters(path)` 读取第一个工作表。必需表头是 `SKU`、`成本`、`跨境价`、`折扣价`、`热销标记`，可选表头是 `上架时间`；列顺序不限。SKU 必须是文本，去掉首尾空格后精确匹配，重复 SKU 会报错。成本与价格必须是有限非负数；显式 `0` 与空白不同。热销标记只接受 `1` 或 `2`。输入格中的公式不算运营显式值，会报错。

空白参数保留为缺失，不借用相似 SKU 的数值。PR3 要求本轮每个 SKU 的成本、跨境价、折扣价均有运营显式值；热销标记为空才使用默认 `2`。仓库产品资料的 `创建时间` 已由业务确认是真实上架时间，按精确 SKU 读取。旧映射表中若显式填写 `上架时间`，仅接受有效的 ISO 日期或日期时间；PR3 将其与仓库产品时间核对，不用它覆盖商品资料。

PR2 的 `prepare_operator_sku_map(template_path, ...)` 与 `resolve_sku_parameters()` 仍提供历史模板参考能力，但 PR3 完整五表生成不调用它们，也不从模板历史兜底。新前端上传表须保留 `SKU`、`成本`、`跨境价`、`折扣价`、`热销标记` 表头，其中热销标记的值可空；旧版 `上架时间` 列可以保留以便兼容读取。

真实九表模板、运营映射表、价格与成本数据均保存在本机受控资产或运行产物中，不进入 Git 或安装包；只有无历史业务数据的骨架资源随应用发布。
