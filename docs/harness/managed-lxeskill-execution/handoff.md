## 调用链与权限

聊天中的 `vietnam-stock-recommendation` Skill 判断意图和附件优先级 → `managed_lxeskill` 接收登记命令 ID；唯一附件绑定时由宿主选取附件 ID，多附件确认后才可显式传选定 ID → Runtime 按当前/紧邻上一条真实用户消息核验附件来源与 XLSX 文件；遇会话压缩或无法识别的中间用户消息时拒绝复用紧邻附件 → Agent CLI 宿主使用现有受管 Python 构造固定 CLI 参数，注入当前会话工作区和 Skill 范围 → Python 原有 bind 或 generate 逻辑执行 → Runtime 校验 terminal 和当前工作区内的最终 XLSX → Agent 确认成功后用 `send_files` 交付。

Read Only 不执行；Workspace Write 可调用登记命令，但受控宿主可写应用内部数据目录，这不扩大模型通用文件权限。桌面通用 `exec` 遇到登记命令会在审批前提示改用受控工具；其他命令仍遵循原权限和审批。工具调用失败不自动重试或回退到 `exec`。绑定和生成是两个独立调用，是否继续由 Skill 判断；文件不会由受控工具自动发送。

## 声明式 Skill 预选

仓库 Skill 可在自身 frontmatter 声明明确的业务短语、附件扩展名、内部只读探针命令和紧邻确认短语。Runtime 只提供通用可选回调，宿主仅在一个启用的仓库 Skill 命中时，把该 Skill 通过现有显式加载流程放进首次模型请求；用户显式 `/skill` 优先，自动预选不会再注入另一个 Skill。公共层没有越南关键词或专属路由。模型继续判断是否绑定、生成和调用 `send_files`，预选本身不会执行这些命令。多 Skill 命中、原始雅仓导出、含糊库存问法按普通路由处理。

裸上传唯一 XLSX 时，宿主从网关构造的本轮 `local_file` 块核验附件身份和磁盘文件；本轮消息此时尚未写入会话记录，因此不能提前从记录表读取。紧邻上一轮澄清只读取已持久化的附件记录，且要求上一轮用户消息已激活同一 Skill。两条路径均复用现有附件来源核验；只读 Python 探针检查第一张表的必需表头，不读 SKU 行、不绑定，也不返回路径。探针异常留下脱敏实际诊断并走普通路由；多附件或更早历史附件不探测。

## 验证结果

- 2026-10-06 最终定向复跑：Runtime/Skill/受控工具相关 7 个文件 **180 通过、0 失败**；Agent CLI 预选 **15 通过、0 失败**；权限回归 **19 通过、0 失败**；Python `lxeskill` 与 `infra` **432 通过、2 跳过**，资产规则及 SKU store **83 通过、0 失败**。Runtime 与 Agent CLI 类型检查、Agent CLI 构建通过。新增错误处理测试曾先失败、修复后通过。自动测试使用合成文件、假 CLI 或假模型，没有读取真实 SKU 表，也没有请求雅仓生产接口；跳过项不计为通过。
- 随后针对长会话中断补了受控附件邻接回归：Runtime 中断标记不再挡住紧邻上一条真实用户上传，旧格式标记也能识别；普通匿名用户消息与压缩边界仍拒绝复用。越南 Skill 明确重新上传是新请求，同一轮取消才停止继续弹窗；查询时不靠长历史推断是否已绑定，重复表由受信 bind 返回 `unchanged`。相关 5 个测试文件 **158 通过、0 失败**，Runtime 与 Agent CLI 类型检查通过。该结果只验证可复现的代码边界与 Skill 文本；随后用户在更新服务的同一长聊天按 A→B→A 裸上传及纯文字查询复测，反馈“测试没有问题”。
- 在本轮预选改动前，macOS Desktop 新聊天中已绑定 SKU 表的“查询越南备货”曾真实生成并交付最终 XLSX；该次模型先做了多余的 Skill 查找。更早的一次绑定后生成遇雅仓连接超时，未交付文件。预选改动后，首次重启服务的日志分别确认一次 `generate → send_files` 和一次 `bind → generate → send_files` 成功完成，均无无关工具调用；用户也反馈看到了可点击的“仅绑定 / 绑定并查询”选择框，并收到了最终 XLSX。再次重启后的同一轮日志确认 `ask_user_question → bind` 成功；用户确认这次只测试了“仅绑定”，没有再次运行生成。两次重启之间没有生产代码修改。
