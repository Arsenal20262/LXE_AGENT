# 新客户端旧业务 Token 清理

桌面和独立飞书网关的日常公司业务访问使用已有设备鉴权。服务器兼容入口仍保留，本次没有修改或部署服务器。

桌面不再申请、刷新、缓存或注入旧业务 Token，也不再因 Token 更新重启网关。服务器地址和统计启用状态取自有效接入配置；Skill 范围继续由 CLI cloud-context 查询。模型更新和接入完成的生命周期保持原行为。

`data_server_api_key` 仍是设备身份凭据，供身份验证、管理员和 ERP 网页登录使用，不能按旧名称误删。旧 secrets.bin 中的业务 Token、ERP 专用 Key 和赛狐专用 Key 被解析时忽略，后续保存不再写回；不增加版本号，不要求重新接入。

公司赛狐 MCP 默认保持关闭，使用 `X-LXE-Client: cli`。已存在的 MCP 配置不再自动转换；公司连接若有旧 Bearer、Authorization 或 Cookie 配置会报告错误，需显式调整配置。连接器启停、工具名单和超时保持原值。其他 MCP 的认证能力保留。

研究在线采集器已淘汰，已有采集文件不动。离线分析、渲染和停售核对继续使用 `scripts/source_comparison_helpers.py`。

统计失败后继续保留本地记录，按已有退避重试；409 不形成永久阻断。此次不修改上传确认、进度或服务器归属规则。飞书网关 `usage:repair` 的管理读取仍使用单独管理凭据，不传入日常 Agent。

本轮只交付本地代码和测试；不推送、不部署、不重启生产网关、不生成安装包。MCP 启动检查的恢复机制另行处理。
