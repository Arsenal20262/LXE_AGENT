# 桌面自动识别设备与权限

桌面不再要求先导入 Enrollment 才查询权限。没有接入配置的新目录启动后，通过受管 CLI 的 `cloud-context` 查询 `http://10.88.0.1:8000/api/v1/device-context`。已有完整接入配置继续使用其中的服务器地址；切换绑定期间不给业务进程提供地址，也不改用默认地址。

## 查询与接入分开

查询只依赖服务器地址和实际网络身份。CLI 保持无 Token、Cookie、系统代理、重定向和自动重试的规则。启动、手动刷新、每 60 秒查询；同一轮合并请求，停止或切换时取消并忽略迟到结果。

查询成功后，桌面展示设备、权限模板、分配版本、模板发布版本和四类授权。Skill 范围来自 `skill_types`，入口来自 `desktop_features`，业务服务和 ERP 动作如实展示。实际业务仍由服务器逐次鉴权。

接入配置和凭据状态仍独立保留：API 识别成功不表示已安装或接管 WireGuard，不申请设备凭据、不配置模型、不授予管理员登录资格。ERP 网页和管理员登录仍需要原来的身份凭据。没有凭据时显示缺少配置，不把它说成没有业务权限。

`LXE_DATA_SERVER_URL` 使用统一公司地址解析，不依赖 Enrollment、权限快照或 Token。统计上传的 `LXE_DATA_SERVER_ENABLED` 仍使用原条件；新目录发现设备不会自动上传。赛狐 MCP 继续使用固定入口、原生请求头、显式开关及工具范围，不自动启用。实例 ID、上传进度和历史数据不转移。

## 身份和缓存

自动识别的身份保存在现有加密存储的 `cloud_observed_device`，完整权限在 `cloud_permission_snapshot`，不会伪造一份完整 Enrollment。旧权限缓存仍可读取，未记录的业务服务和 ERP 动作显示“待查询”。保留旧备货类型的缓存转换与模板版本校验，不引入在线旧类型兼容。

- 首次没有身份记录时接受合法服务器身份。
- 已有完整接入配置时核对设备 ID 和 WireGuard IP，不匹配则清空权限，继续通过原切换绑定流程处理。
- 只有自动识别记录时，身份变化清空权限并提示确认；确认会重新查询，只有新响应与待确认身份一致才接受。再次变化继续等待确认。
- 断网、超时、服务器失败保留上一次权限并标记缓存；协议或 CLI 错误保留真实诊断，不接受新数据。
- 401／403 或身份不匹配清除内存和持久化权限，但保留已识别身份。重启不会恢复已清空的授权。

桌面状态新增 `device_context`，保留原接入字段含义；IPC 增加 `refreshCloudContext` 与 `confirmCloudDevice`。刷新权限不会触发 WireGuard 重连或安装。

## 验证与发布边界

定向测试覆盖无接入发现、四类授权、身份确认及再次变化、未支持接入工具的平台轮询、切换与停止、版本异常、旧缓存及拒绝后重启。原有设备身份、模型、MCP 和上传测试继续运行。

可重复执行的隔离页面验收：

```bash
bun scripts/device-context-acceptance.ts
```

该脚本使用临时配置、实际桌面服务、实际受管 CLI、本地模拟上游和真实 Electron 渲染组件；不启动完整 Agent，也不调用公司服务器。覆盖识别、503 缓存、身份变化确认、403 清权、中英文及窄窗口。截图默认保存在系统临时目录 `lxe-device-context-acceptance`，可用 `LXE_ACCEPTANCE_ARTIFACTS` 指定。

本轮仅交付本地代码和验证，不推送、不部署、不修改 Mac mini、不生成安装包。真实服务器若尚未完成备货类型迁移，仍返回 `amazon_replenish`；新 Skill 类型加载的真实验收等待服务器迁移，不通过客户端在线别名掩盖升级差异。

完整验证结果见本任务交付记录；页面验收验证了独立权限面板与真实服务链路，未冒充完整桌面所有页面或真实业务操作的验收。
