## 目标与边界

当前基线为 PR6 的 `cc77bf20`，只改变越南 SKU 参数表的业务上传入口：业务人员在聊天中附上 `.xlsx`，只请求绑定时只绑定；附表查询或生成越南备货时先绑定，成功后再生成，失败时停止。没有待处理新附件时才沿用受信 `current`。工作台保留当前版、上一版和回滚展示，移除 SKU 上传按钮与已停用的完整模板卡片。生成命令仍无参数。其他业务资产、雅仓导出、五表计算、Desktop 内部 IPC 和四项长期参数不在 PR7 改动范围。

此前本机开发预览目视检查过旧模板隐藏、SKU 上传按钮移除和当前版显示；它不是 Windows 安装包或真实聊天模型回放。真实雅仓、用户聊天附件选路、最终同步 `main` 后的全量回归均未由上述结果证明。

此前收口回合运行了 Desktop 附件与 Gateway 本地对话定向测试（`26 passed`）以及 Provider 原样路径传递定向测试（`1 passed`），此次未复跑。它们只验证附件路径传递。此前同轮尝试运行整个 Provider 测试文件得到 `51 passed, 1 failed`，失败项是沙箱内 `Bun.serve` 端口监听 `EADDRINUSE`；相关定向用例随后通过，整文件不能记作通过。

此次仅为 PR7 附件规则增加现有 Skill 发现测试中的文本契约断言：当前消息恰好一个附件且为 XLSX、紧邻上一条用户消息的明确确认/澄清/继续、禁止更早历史，以及多附件即使只有一份 XLSX 也先确认。修改 Skill 前该测试文件 `12 passed, 1 failed`，修改后 `13 passed, 0 failed`。它验证 Skill 声明可以加载且文字包含这些边界，不是四个真实模型场景的执行验收。

本次自动绑定修订继续在同一测试里增加文字断言：附表查询/生成先绑定、失败不沿用旧 `current`、没有待处理新附件或紧邻附件已成功绑定时沿用 `current`，以及东南亚入口转交越南 Skill。从仓库根运行修改后的整个 `skills.test.ts`，结果 `13 passed, 0 failed`；静态断言仍不能证明真实模型会做出这些选择。

此前收口回合还用固定脚本代替模型决策，经真实 `TypeScriptAgentRuntime.runTurn` 回放六种合成场景，结果 `6/6` 符合固定脚本预期：成功时读当时的 Skill、绑定、生成、发送最终文件；没有可选附件、双附件、CSV 在读 Skill 后停；绑定失败和错误 XLSX 在绑定后停。没有可选附件的场景并非明确确认紧邻唯一附件；此项此次未复跑，也未覆盖该例外，只证明 Runtime 分发与固定脚本的终态控制，不能当作真实模型验收。

此次另做完全脱敏的本地预演：临时脚本和结果只在系统临时目录，没有新增仓库文件。实际加载 Runtime 模块，但仅用内存会话、七条合成规则、合成附件、假工具与固定假模型；没有读取真实 Skill、真实 system prompt、真实附件或业务文件，也未访问雅仓。六个场景 `6/6` 符合预设：成功为 `bind_sku → generate → send_files`；没有可选附件（也未明确确认紧邻唯一附件）、多附件、非 XLSX 均无工具调用；bind 失败和内容错误 XLSX 仅调用 `bind_sku`。假 Provider 接收每个请求前执行白名单校验，共 11 次，并清理 Runtime 环境消息；未出现无关 Skill 或同批依赖调用。外部模型调用为 `0`，该预演未覆盖紧邻确认例外，因此只证明本地预检和假模型流程，**不证明脱敏条件下的真实模型决策，更不等同于生产 Skill / CLI / 雅仓真实链路验收**。

此前普通沙箱内最小模型连接返回 `Connection error`；自动审批后的沙箱外合成 `ping` 得到 `PONG`，只证明连接可用。此前拟发送非公开仓库 Skill/system prompt 的完整 Runtime 回放两次被自动审批拒绝，六个真实模型场景未运行。用户现已明确禁止外发真实仓库与业务内容，仅批准完全脱敏回放；此次自动审批仍拒绝了给临时脚本增加 DeepSeek 网络调用和环境 API key 读取能力，认定超出其允许的本地回放范围，并明确要求不得绕过。补丁未应用、外部模型调用未发生，**真实模型决策未验证**。
