# 受控 lxeskill 业务执行入口设计

## 目标与现状

桌面会话默认是 Workspace Write。越南 Skill 目前通过通用 `exec` 运行 `lxeskill vietnam sku bind` 和 `lxeskill vietnam stock recommend`。CLI 初始化、长期 SKU 输入、日志、雅仓锁及 Python 自有数据库会写应用管理的数据目录，而默认会话工作区只覆盖 `var/workspace/`。因此模型会在命令启动前申请整次 Full access。

目标是在业务人员通过聊天绑定新 SKU 表或生成越南备货清单时，免除这种针对应用内部写入的逐次审批，同时不扩大普通 `exec` 的权限。越南计算、雅仓来源、Workbook、持久 current/previous、结果交付契约维持现状。

## 方案选择

- 仅关闭日志、迁移数据根或把整个 `var/` 设为会话工作区：无法完整解决长期状态写入，还会扩大模型可写范围；不采用。
- 根据 `lxeskill` 字符串自动放开通用 `exec`：shell、参数和子进程难以形成安全边界；不采用。
- 新增**宿主管理的登记业务命令入口**：复用现有 `OneShotCliRunner`，由宿主映射固定 argv、检查附件与结果，通用 `exec` 和其审批不变；采用。这里的安全边界是严格的命令登记与参数校验，并非声称宿主进程仍受会话文件沙箱约束。

## 契约与权限边界

1. Catalog 显式标记可使用受控入口的业务命令；本轮只登记越南 SKU 绑定与越南备货生成。公共 Runtime 只解释登记字段，不出现越南专属 `if`，其他命令保持原执行方式。Python 和 Bun 对新增 catalog 字段做一致校验。
2. 新工具接收命令标识与结构化参数，不能接收 shell 字符串、任意 argv、cwd、环境变量或绝对路径。宿主从登记项构造固定 argv；未登记、不可见或超出参数契约的请求在启动前拒绝。Read Only 会话不得通过该入口写长期数据或结果；Workspace Write 可运行登记命令，但不会改变会话模式。
3. 绑定输入使用宿主核验的附件 ID，不使用模型提供的路径。当前或合规紧邻消息只有一份附件时，模型可省略 ID，由宿主从会话记录自动选取；已确认的多附件选择才显式传 ID。宿主解析路径，并证明附件来自当前用户消息，或来自紧邻上一条用户消息且没有后续候选。模型仍按 Skill 语义判断当前消息是否明确确认、澄清或继续处理；宿主只验证可客观证明的时序、唯一选择、扩展名和路径身份。多附件一律先确认选哪一份，未确认不得运行。非 XLSX、历史附件或无法证明紧邻关系时拒绝并要求重新上传。Python `bind` 继续校验 Workbook 内容。
4. 生成命令不接受文件路径或聊天临时参数，只读取受信 current。绑定和生成保持两个独立调用：绑定失败、超时、取消或结果契约异常后不能继续生成，也不能发送文件。现有 Skill 仍决定用户意图与先后顺序，不由工具二次调用模型。
5. 宿主沿用桌面注入的受管 Python、Office Kit 和业务凭据，保留现有超时、取消、输出上限、实际错误脱敏与审计。禁止静默重试或降级到通用 `exec`。宿主执行器可写应用内部目录，这是明确的受信操作；不能向模型开放相同文件权限。
6. 绑定成功的 terminal 必须 `files=[]`。生成成功的 terminal 只能把位于当前工作区产物目录的最终 XLSX 声明为可交付文件；路径越界、文件缺失或结果形状异常都拒绝。`send_files` 仍由 Agent 在验证终态后调用一次。

## 预期修改范围

- `python/lxeskill_cli/lxeskill/catalog.json`：登记受控命令及参数、文件契约。
- `packages/agent/runtime/src/tooling/`：结构化工具、catalog 校验、权限与输出校验；通用 `exec` 沙箱不改。
- `apps/agent-cli/src/runtime-host.ts` 和必要的会话存储只读查询：接入已有一次性 CLI 执行器，验证附件 ID 的会话与时序。
- `skills/vietnam-stock-recommendation/SKILL.md`：改用结构化工具，保持当前消息优先、紧邻澄清、多附件确认、先绑定后生成和最终 XLSX 交付规则。
- 权限文档与越南 handoff：准确描述受控入口和未改变的通用命令边界。

如无法在现有记录中无歧义判断紧邻附件，必须拒绝该输入；不得退回搜索历史附件或让模型猜路径。实现时若发现需要扩大到 Desktop、Python 数据层重构或修改通用沙箱，应停止并重新审阅范围。

## 验收与发布边界

- 仅用合成附件和假 CLI 覆盖：当前唯一 XLSX、紧邻唯一 XLSX 的明确确认/继续、较早历史附件、多附件、非 XLSX、绑定失败、超时/取消、生成成功与结果路径越界。
- 权限回归验证：Read Only 不写，Workspace Write 登记命令不弹 Full access，普通 `exec` 和未登记命令仍遵循原审批，不能注入 shell/路径/环境变量。
- 跑 catalog 的 Python/Bun 双端契约测试，以及 Runtime、Skill、Agent CLI、涉及的 Desktop/IPC 定向测试和 build/typecheck。报告真实运行结果；合成测试不等于真实模型、雅仓或 Windows 安装版验收。
- 自动测试不读取真实业务文件、不调用生产雅仓。真实链路需在可控环境另行验收，遇 401/403/429 仍按现有规则停止。
- 在独立 worktree 完成与验证后，作为独立提交更新现有越南 PR7 源分支；保持 PR7 的 base/head 分支关系，不创建新 PR，也不改 PR1–PR6。提交、push、merge 分别遵守仓库审批要求；向组长仓库提交和合并由用户操作。

## 补充：越南 Skill 的轻量预选

桌面新聊天的实测表明，已绑定 SKU 表的备货查询最终交付了 XLSX，但模型先调用 `find`、失败的 `ls` 和 `read` 才看到 Skill；约 50 秒用于真实生成，其余时间包含这些多余的查找轮次。此处只缩短 Skill 路由，不让宿主代替模型绑定、生成或发送文件。

- 公共 Runtime 提供可选的 Skill 名称预选回调。在首次模型请求前，用户显式 `/skill` 优先，不叠加不同的自动预选 Skill；没有显式指定时，预选名复用既有 `resolveInvokedSkill`、可见性校验、激活和会话记录流程。用户原文、附件记录、权限策略和通用工具行为不变；公共 Runtime 不含越南业务词或表头。
- Skill 可在自身 frontmatter 声明少量高置信文字短语，或声明附件扩展名、只读探针命令 ID 和紧邻确认短语。通用预选器只读取当前可用的仓库 Skill 声明；Desktop 上恰好一个 Skill 命中才预选，零个或多个命中都走普通模型路由。声明不包含含糊的“看看越南库存”、雅仓原始报表等短语；若流程询问文字恰好包含声明的操作短语，预选只加载 Skill，Skill 仍须识别这是流程咨询而不得执行。宿主与公共 Runtime 不写 `if vietnam` 或越南词句到 Skill 名称的固定映射，后续国家只需自己的声明与业务探针。
- Desktop 当前消息只有一份 `.xlsx`、没有文字或文字恰好是声明的“仅绑定”“绑定并查询”时，通用预选器按 Skill 声明调用内部、不可暴露给模型的 `lxeskill vietnam sku probe` 只读命令，检查越南 SKU 表的第一张表表头。探针复用现有五个参数表头与文件安全上限，只返回布尔匹配；不遍历或回传 SKU 行，不绑定、不记录路径或单元格值。本轮附件来自网关构造的 `local_file` 块，因为预选时该消息尚未写入会话记录；宿主仍验证块的时序、文件身份和大小。紧邻下一条若明确回复该 Skill 声明的“仅绑定”或“绑定并查询”，且上一条唯一附件已预选该 Skill，可从已保存会话附件记录读取并再次只读识别；更早附件不可复用。不匹配、多附件和非 XLSX 均保持普通路由；探针异常记录脱敏后的真实诊断并走普通路由。首次命中后预选越南 Skill，由 Skill 询问“仅绑定 / 绑定并查询”。
- 探针命令须在 catalog 中显式标记为仅供预选的内部只读命令；通用宿主只接受此类登记、固定 `source_path` 参数和严格的布尔成功结果。附件路径仍由会话记录及现有受控附件来源校验取得，不从文件名、模型文本或历史目录猜测。
- 裸上传且未说明用途时，Skill 明确调用现有 Desktop `ask_user_question`，提供“仅绑定 / 绑定并查询”两个单选项；用户选定后才继续，跳过则停止。明确查询或生成时不增加该确认，模型继续按现有 Skill 调用受控 bind → generate → send_files。未绑定时，生成命令在访问雅仓前返回 `sku_parameter_map_required`，模型明确提示先上传绑定。不增加宿主业务状态机、直接工具执行或新数据库；不修改雅仓网络策略。
- 用合成文件和假模型/假 CLI 验证：明确问法首次请求已包含 Skill 且无查找轮次；裸上传匹配时询问两选项；无关 XLSX 不误路由；显式 Skill 不重复；禁用 Skill 不注入；真实附件来源与权限检查仍有效。真实模型的两轮及同轮绑定生成需另行验收，静态测试不得写成已通过。
