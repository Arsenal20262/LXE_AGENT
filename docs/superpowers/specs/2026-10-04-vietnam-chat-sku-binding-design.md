# 越南备货：聊天上传并绑定 SKU 参数表

## 目标与边界

业务人员在 LXE Agent 聊天窗口附上 `.xlsx` 越南 SKU 参数表，明确要求绑定时，应用校验文件并保存为长期生效的当前版。附表查询或生成越南备货时，即使没有说“绑定”，也先绑定新表，成功后再启动生成；绑定失败不得沿用旧版。没有待处理新附件，或紧邻附件已成功绑定时，查询或生成才沿用已绑定的当前版。只绑定表时不调用雅仓。

本段是 PR7 后续收口修订：补充“附表查询/生成自动先绑定”的入口规则。原始设计中的独立绑定命令、长期 `current` 和工作台范围保持不变。

本改动从 PR6 `codex/vietnam-stock-pr6-partial-mapping` 的已验证提交开始，在独立分支 `codex/vietnam-chat-sku-binding` 实施，依赖 PR6 的稀疏映射行为。只改变越南备货的输入方式和相关界面；其他五类聊天管理资产、雅仓导出、五表计算规则、内置骨架、四项长期参数和文件交付规则不变。

旧“越南备货清单模板”已不参与当前五表生成。工作台不再展示该卡片，也不把它计入就绪数量；保留底层注册、历史文件和旧离线辅助接口，避免破坏兼容。工作台保留“越南 SKU 参数表”的当前版、上一版及回滚展示，但不再提供上传按钮；空状态指引改为在聊天中上传。其他资产卡片不变。

## 聊天流程

越南备货 Skill 同时识别三种意图：只绑定新版 SKU 参数表、没有新附件时使用已绑定表生成备货清单、附表查询或生成时先绑定新版再生成。查询指请求本轮备货结果；仅询问功能或流程不触发生成。仅有附件而用途不明时先询问，不把任意 Excel 自动当作 SKU 表；多附件必须先确认所选文件，即使其中只有一份 `.xlsx`，确认前也不凭文件名或其他线索自行选择。

当前消息恰好只有一个附件且它是 `.xlsx` `local_file` 时，绑定优先使用该附件的真实绝对路径；绑定命令负责校验文件内容。当前消息没有附件时，仅在紧邻上一条用户消息刚上传了可唯一确定的 `.xlsx` 附件，且当前消息明确是在确认、澄清或继续处理该附件（包括要求“查询越南备货”）、期间没有新候选且该附件尚未绑定成功时，允许继续使用那个紧邻附件；不要求 Skill 先询问用途。若上一条有多个附件，本条还须明确选定其中一份 `.xlsx`；无法唯一确定时要求重新上传单一附件。本轮提供非 `.xlsx` 附件时拒绝绑定，不改用旧 `current` 生成。其他情况不得跨多轮复用历史附件、从更早消息搜索旧文件、根据“之前上传过”猜测路径，也不得扫描本机目录或使用历史模板。桌面会话附件是对原文件路径的引用，受信存储在绑定时重新检查并复制文件；命令层只校验路径和文件内容，无法单独证明路径来自哪条消息，因此附件来源约束必须在 Skill 与模型执行测试中检查。

新增独立业务命令 `lxeskill vietnam sku bind --source-path <选定附件绝对路径>`。命令使用独立业务模块，只接受一个 `.xlsx` 文件路径，调用现有受信 SKU 版本存储；它不调用雅仓、不生成工作簿，也不把通用 `x-lxe-asset-slot` 升版机制用于越南槽位。catalog 为新命令的 `source_path` 标注 `.xlsx` 的 `x-lxe-file-input` 及上传指引，不标注 `x-lxe-asset-slot`；SKU 槽继续保持 `management: desktop`。现有内部 Desktop 安装与回滚命令保留以兼容已有调用。生成命令 `lxeskill vietnam stock recommend` 保持无参数，仍从受信 current 取得本轮私有快照。

聊天收到“绑定并生成”或附表查询/生成请求且有待处理新附件时，先执行绑定命令并检查终态 `ok` 与 `data.success`；只有绑定成功，才执行一次现有生成命令。绑定失败时停止，不调用雅仓，不沿用旧 `current`，也不把附件路径直接传给生成命令。没有待处理新附件或紧邻附件已成功绑定而请求生成时沿用受信 `current`；若没有受信 `current`，在雅仓调用前提示在聊天中上传并绑定 SKU 表。绑定成功后明确报告是新版本还是内容未变化，并说明后续生成会沿用当前版；不得在未校验终态时声称已绑定。

## 版本、安全与错误

绑定命令先读取现有受信清单的 revision，再以该 revision 调用现有 `install_sku_map`。安装仍在锁内核对 revision，沿用候选文件的普通文件、大小、ZIP 安全、表头、唯一 SKU、数值精度、内容摘要、原子替换与 current/previous 规则。若读取清单后发生并发更新，返回现有真实冲突诊断，不静默覆盖，也不自动重试。清单损坏、附件消失或非法、表内容不合格时返回脱敏且有界的实际错误；当前版保持不变。

绑定一个与当前版内容完全相同的文件是无变化结果，不消耗上一版回滚位。成功安装新表后，已有聊天中的生成任务仍按各自开始时取得的私有快照继续，不能中途切换映射表。工作台回滚继续通过现有 revision 保护和受信上一版执行。旧完整模板文件不删除、不用作成本或价格兜底。

## 界面与验收

工作台从统一资产列表中过滤旧模板卡片，使列表和“已就绪”统计使用同一份过滤结果。SKU 卡展示当前文件、上一版及回滚按钮；删除“上传映射表”按钮与相应的“在这里上传”提示，改为聊天上传说明。工作台刷新后能看到聊天绑定的新版本；绑定命令的回复直接告知结果，不依赖用户打开工作台才能得知是否成功。

使用合成 XLSX 验证：首次绑定、替换、相同内容重复绑定、非法表与损坏清单保留旧版、并发 revision 冲突、回滚，以及只绑定不调用雅仓。Skill 文本契约覆盖当前消息恰好一个 XLSX 附件优先、紧邻上一条用户消息的 XLSX 被本条明确确认/澄清/继续处理时允许复用、附表查询/生成须先绑定且失败停止、没有待处理新附件或紧邻附件已成功绑定时才沿用 `current`、更早历史不可复用，以及多附件即使只有一份 XLSX 也先确认；catalog 测试覆盖 `.xlsx` 输入元数据。这些静态检查不能证明真实模型会遵守规则，真实 Agent/Runtime 决策须另行验收。界面测试覆盖旧模板不显示且不计数、SKU 上传按钮移除、当前/上一版与回滚仍显示、其他资产不受影响。改动 catalog 后按项目规范运行 Python 与 Bun 两端契约测试；使用定向测试、Renderer typecheck/build、`git diff --check` 和 `git status` 验证，不调用生产雅仓。
