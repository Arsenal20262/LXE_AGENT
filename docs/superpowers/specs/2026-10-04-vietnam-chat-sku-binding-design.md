# 越南备货：聊天上传并绑定 SKU 参数表

## 目标与边界

业务人员在 LXE Agent 聊天窗口附上 `.xlsx` 越南 SKU 参数表并明确要求绑定后，应用校验文件并保存为长期生效的当前版。以后只说“生成越南备货清单”即可沿用当前版；若同一条消息同时要求绑定和生成，先确认绑定成功，再启动生成。只绑定表时不调用雅仓。

本改动从 PR6 `codex/vietnam-stock-pr6-partial-mapping` 的已验证提交开始，在独立分支 `codex/vietnam-chat-sku-binding` 实施，依赖 PR6 的稀疏映射行为。只改变越南备货的输入方式和相关界面；其他五类聊天管理资产、雅仓导出、五表计算规则、内置骨架、四项长期参数和文件交付规则不变。

旧“越南备货清单模板”已不参与当前五表生成。工作台不再展示该卡片，也不把它计入就绪数量；保留底层注册、历史文件和旧离线辅助接口，避免破坏兼容。工作台保留“越南 SKU 参数表”的当前版、上一版及回滚展示，但不再提供上传按钮；空状态指引改为在聊天中上传。其他资产卡片不变。

## 聊天流程

越南备货 Skill 同时识别三种明确意图：绑定新版 SKU 参数表、使用已绑定表生成备货清单、先绑定再生成。仅有附件而无法确认用途时先询问，不把任意 Excel 自动当作 SKU 表。多个候选附件无法明确对应时先确认所选文件，不凭文件名猜路径。Skill 使用本次请求所附 `local_file` 的真实绝对路径；若刚发送的文件消息用途不明，Skill 先询问，下一条回复明确指向该文件且期间没有新候选时，可继续使用那条紧邻消息的附件。不得扫描本机目录、选用更早的历史附件、历史模板或未受信路径代替。桌面会话附件是对原文件路径的引用，受信存储在绑定时重新检查并复制文件；命令层只校验路径和文件内容，无法单独证明路径来自哪条消息，因此附件来源约束必须在 Skill 与模型执行测试中检查。

新增独立业务命令 `lxeskill vietnam sku bind --source-path <当前附件绝对路径>`。命令使用独立业务模块，只接受一个 `.xlsx` 文件路径，调用现有受信 SKU 版本存储；它不调用雅仓、不生成工作簿，也不把通用 `x-lxe-asset-slot` 升版机制用于越南槽位。catalog 为新命令的 `source_path` 标注 `.xlsx` 的 `x-lxe-file-input` 及上传指引，不标注 `x-lxe-asset-slot`；SKU 槽继续保持 `management: desktop`。现有内部 Desktop 安装与回滚命令保留以兼容已有调用。生成命令 `lxeskill vietnam stock recommend` 保持无参数，仍从受信 current 取得本轮私有快照。

聊天收到“绑定并生成”时，先执行绑定命令并检查终态 `ok` 与 `data.success`；只有绑定成功，才执行一次现有生成命令。绑定失败时停止，不调用雅仓，也不把附件路径直接传给生成命令。单纯请求生成而没有受信 current 时，在雅仓调用前提示在聊天中上传并绑定 SKU 表。绑定成功后明确报告是新版本还是内容未变化，并说明后续生成会沿用当前版；不得在未校验终态时声称已绑定。

## 版本、安全与错误

绑定命令先读取现有受信清单的 revision，再以该 revision 调用现有 `install_sku_map`。安装仍在锁内核对 revision，沿用候选文件的普通文件、大小、ZIP 安全、表头、唯一 SKU、数值精度、内容摘要、原子替换与 current/previous 规则。若读取清单后发生并发更新，返回现有真实冲突诊断，不静默覆盖，也不自动重试。清单损坏、附件消失或非法、表内容不合格时返回脱敏且有界的实际错误；当前版保持不变。

绑定一个与当前版内容完全相同的文件是无变化结果，不消耗上一版回滚位。成功安装新表后，已有聊天中的生成任务仍按各自开始时取得的私有快照继续，不能中途切换映射表。工作台回滚继续通过现有 revision 保护和受信上一版执行。旧完整模板文件不删除、不用作成本或价格兜底。

## 界面与验收

工作台从统一资产列表中过滤旧模板卡片，使列表和“已就绪”统计使用同一份过滤结果。SKU 卡展示当前文件、上一版及回滚按钮；删除“上传映射表”按钮与相应的“在这里上传”提示，改为聊天上传说明。工作台刷新后能看到聊天绑定的新版本；绑定命令的回复直接告知结果，不依赖用户打开工作台才能得知是否成功。

使用合成 XLSX 验证：首次绑定、替换、相同内容重复绑定、非法表与损坏清单保留旧版、并发 revision 冲突、回滚，以及只绑定不调用雅仓。Skill 和 catalog 测试覆盖当前附件真实路径、缺附件提示、同一消息绑定后生成、失败时停止、无附件生成沿用 current。界面测试覆盖旧模板不显示且不计数、SKU 上传按钮移除、当前/上一版与回滚仍显示、其他资产不受影响。改动 catalog 后按项目规范运行 Python 与 Bun 两端契约测试；使用定向测试、Renderer typecheck/build、`git diff --check` 和 `git status` 验证，不调用生产雅仓。

同步现行业务说明、资产契约、SKU 表说明、Skill 清单、Skill 和交接文档，说明聊天绑定是越南 SKU 表唯一向业务人员开放的上传入口；原有受信 Desktop IPC 保留作兼容调用，但工作台不再提供上传操作。历史 PR3–PR6 规格与交接保留当时口径，不回写改成新流程。提交、推送、创建 PR、合并分别遵循仓库审批要求；本地实现与合成测试不能代替真实雅仓和 Windows 安装包现场验收。
