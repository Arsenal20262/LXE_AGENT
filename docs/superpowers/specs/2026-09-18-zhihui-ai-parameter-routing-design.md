# 智汇 TMS AI 参数翻译路由设计

## 目标

将智汇 TMS 商品查询从“运行时通过关键词解析自然语言”改为“先由 AI 将用户请求翻译成受约束的业务参数，再由代码校验并进入现有导出流程”。用户仍然需要在确认卡中明确确认后，系统才执行生产导出。

## 当前问题

现有 Desktop 入口在模型回合之前调用 `matchZhihuiProductRequest()`，通过“菲律宾、库存、销量”等文本关键词决定是否进入智汇流程。这种方式容易随着自然语言表达增加而不断扩展规则，也无法清晰表达用户的结构化意图。

## 推荐方案

增加一个独立的 AI 意图翻译层。AI 只负责把当前用户请求翻译为 JSON 参数或返回无法识别；业务代码负责 schema 校验、平台和仓库白名单、字段白名单、确认流程和生产调用。

### 参数契约

```ts
type ZhihuiProductRequest = {
  platform: "zhihui_tms";
  warehouse: "PH";
  intent: "product_export";
  fields: Array<"product" | "sku" | "sales" | "inventory" | "inbound" | "listing">;
};
```

参数必须满足：

- `platform` 只能是 `zhihui_tms`。
- `warehouse` 只能是 `PH`。
- `intent` 只能是 `product_export`。
- `fields` 只能包含已声明字段，且至少包含一个字段。
- 不接受任意命令、URL、账号、密码、Token、Cookie 或其他执行参数。
- AI 无法确认平台、菲律宾仓库或商品导出意图时返回 `null`，不得猜测。

## 运行流程

1. Desktop 用户提交普通文字请求。
2. Agent 使用结构化输出调用 AI 意图翻译器。
3. 运行时解析并校验 JSON；非法 JSON、未知字段、额外字段、枚举值不匹配或返回 `null` 时，不调用智汇 CLI，继续普通模型路径。
4. 合法参数进入现有智汇确认路由；路由将参数转换为固定的 `tms philippines products-export --action preview` 命令。
5. preview 成功后展示现有确认卡。
6. 只有用户选择“确认执行导出”时，才调用一次 `action=execute`。
7. 登录复用、限速、账号锁、401/403/429 即停、部分合并文件和错误脱敏逻辑保持不变。

## 安全边界

- AI 输出不能直接成为 shell 参数或 HTTP 请求。
- 业务代码只允许固定 Skill 和固定仓库，不根据模型输出拼接任意命令。
- 结构化翻译调用失败不得自动重试成无限循环。
- 不将凭据、Cookie、Session 或 Token 放入翻译请求、日志或持久化消息。
- 用户未确认时只允许 preview，不允许生产 API 或商品数据导出。
- 模型不确定时必须回退普通对话，不做隐式触发。

## 失败处理

- JSON 解析失败：记录脱敏诊断，回到普通模型路径。
- schema 校验失败：不调用 CLI，回到普通模型路径。
- preview 失败：展示真实脱敏错误，不弹出执行确认。
- 用户取消：结束当前导出，不调用 execute。
- execute 遇到 401、403、429、验证码或明显风控：立即停止，不重复请求。

## 代码边界

- 新增独立的参数类型和校验模块，避免把模型解析逻辑混入导出业务。
- Agent runtime 负责发起结构化翻译和处理“不确定/失败”分支。
- `ZhihuiTmsConfirmationRouter` 接收已校验参数，不再负责解析中文关键词。
- Skill 文档改为描述结构化参数入口，同时保留固定命令和生产安全约束。

## 测试要求

- “查询菲律宾库存”“查询菲律宾销量”“查询智汇菲律宾 SKU”能翻译成合法参数并进入 preview。
- “查询库存”“查询智汇订单”“查询雅仓库存”不能生成合法智汇参数。
- AI 返回 `null`、非法 JSON、未知字段、错误平台、错误仓库、错误意图、空字段时均不调用 CLI。
- 合法参数仍必须经过确认卡；普通文字“执行”不能绕过确认。
- 既有登录复用、限速、403/429 停止、部分交付和错误脱敏测试继续通过。

## 暂不做

- 不扩展其他平台。
- 不修改智汇 TMS API、登录、分页、导出字段或风控策略。
- 不允许模型直接调用 Skill 或生成任意 CLI 命令。
