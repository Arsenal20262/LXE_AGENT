# 智汇 TMS 确认式路由设计

## 目标

桌面端用户提出“查询智汇菲律宾销量、库存、SKU、入库或上架时间”等商品数据需求时，系统必须在不调用模型通用检索工具的情况下给出固定导出计划和“确认执行导出”选择。只有用户在该确认卡中选择确认，才运行现有的智汇 TMS 商品导出 CLI。

## 问题与范围

现有运行时把这类请求完全交给模型处理。智汇 Skill 同时要求“先预览”与“明确执行才导出”，但没有一个程序化的决定点。实际会话因此进行了 29 次 `read`、`grep`、`ls` 和一般 `exec` 调用，未调用 `lxeskill tms philippines products-export`，并在用户取消前没有结果。

本设计只处理 Desktop 的智汇 TMS 菲律宾商品全量导出入口。不修改雅仓、马帮、紫鸟或其他 Skill；不改变智汇登录、分页、限速、重试、403/429 停止或账号锁。交付层只对前端暴露一个合并 XLSX，不暴露分页 XLSX。

## 行为契约

### 识别

仅在 Desktop 的普通用户回合中拦截满足以下条件的文本：

- 文本包含智汇上下文（`智汇`、`tms`）；菲律宾是当前唯一受支持的智汇仓库，用户可以省略该词。或者，会话最近一次商品数据请求已明确指向智汇，后续“查询销量”等简短追问沿用这一上下文；
- 文本包含一个商品字段词：`商品`、`SKU`、`销量`、`库存`、`入库`、`上架`；
- 文本未请求订单、物流、发货、采购、财务或独立历史报表。

识别模块返回 `unmatched` 或一个不可变的 `ZhihuiTmsConfirmationRequest`。它不读取凭据、不访问网络、不创建文件，也不决定是否能执行生产调用。

### 预览与确认

对已识别的请求，运行时按以下顺序处理：

1. 使用现有 `OneShotCliRunner` 运行一次 `lxeskill tms philippines products-export --action preview --request <原始用户文本>`。预览是纯计划操作，不访问智汇接口，不生成 XLSX。
2. 将真实、已脱敏的预览结果作为当前回合的说明写入会话和 Desktop 流式结果；说明固定包含“销量等字段归入菲律宾商品全量导出，不代表独立历史销量报表”。
3. 通过现有 `UserQuestionService` 显示一个单选确认卡，选项固定为“确认执行导出”和“取消”。确认卡在等待时保持当前回合，不向模型发起请求。
4. 用户选择“确认执行导出”后，使用同一原始请求运行一次 `lxeskill tms philippines products-export --action execute --request <原始用户文本>`。用户选择“取消”、跳过、停止回合或重启 Agent 时均不执行。

“确认执行导出”是一次性的、与 `session_id`、`turn_id` 和确认 `request_id` 绑定的授权。重复点击同一确认卡由既有 `UserQuestionService` 幂等处理；任何新的回合必须重新预览并确认。

### 执行与结果

执行仍由 CLI 的生产开关、凭据检查、账号锁和请求预算做最终裁决。生产开关关闭、凭据缺失、锁冲突、403、429、验证码或账号异常时，展示 CLI 返回的真实脱敏错误，且不再自动重试。

执行成功时，沿用既有智汇进度事件，前端只收到一个完整合并 XLSX。分页下载结果只在内存校验和合并，不创建或交付分页 XLSX。若后续下载或工作簿校验失败，已完成且校验通过的页会写成一个“部分合并”XLSX；前端仍只收到这一个文件，并同时看到真实脱敏错误、已合并页数和行数。发生 401/403/429 或其他导出阶段失败时立即停止，不能为生成部分结果发起新的智汇请求；若没有已校验数据则不交付文件。绝不将部分合并文件说成完整成功。

## 架构

新增一个深模块 `ZhihuiTmsConfirmationRouter`，其接口只暴露“本回合是否由该流程处理”与处理结果。它隐藏文本识别、预览参数构造、确认卡创建、确认答案校验、单次执行和用户可见结果格式化。

该模块在 `TypeScriptAgentRuntime` 持久化用户输入之后、构建模型上下文之前运行。若结果为 `handled`，运行时完成本回合而不调用模型、Skill 快照或通用 `read/grep/ls/exec` 工具；若结果为 `unmatched`，现有模型回合完全不变。

运行时继续是会话消息、流输出、取消和用量状态的唯一属主。确认路由不直接写 SQLite，也不伪造模型或工具消息。它通过一个窄适配器请求运行时：追加用户可见文本、创建/等待现有确认卡、调用 `OneShotCliRunner`，并将终态交回运行时记录。这使路由测试可以使用内存适配器，不依赖模型或真实 TMS。

```text
用户请求
  -> 智汇确认路由匹配
     -> preview CLI（无网络）
     -> Desktop 确认卡
        -> 取消/停止：结束，无执行
        -> 确认：execute CLI
           -> 现有进度、风控、附件交付
  -> 未匹配：现有模型回合
```

## 错误与取消

- 预览 CLI 不可用或返回失败：回合输出真实脱敏错误，不显示确认卡，也不调用模型。
- 等待确认期间停止回合：`UserQuestionService` 清除待处理问题；路由返回取消终态，零执行。
- Agent 停止或重启：现有问题服务使确认失效；旧 `request_id` 不可恢复或转移到新进程。
- 任一步检查到 `AbortSignal`：立即停止，不进入下一步。
- 确认答案不等于固定确认标签、为空或跳过：视为取消，零执行。

## 测试策略

所有测试使用假 `OneShotCliRunner`，不得调用真实账号或网络。

1. 识别测试覆盖销量、库存、SKU、入库、上架词，非智汇/非菲律宾文本及订单/物流/财务排除词。
2. 路由测试断言匹配请求恰好一次 `preview`、零模型调用，并出现含两个固定选项的确认卡。
3. 确认测试断言选择确认后恰好一次 `execute`，参数的原始请求与预览一致；取消、跳过、停止和重复提交均为零执行或不重复执行。
4. 失败测试断言预览失败不创建确认卡，执行失败保留真实脱敏错误，且 403/429 不触发第二次执行。
5. 运行时集成测试断言路由后的回合不暴露通用工具、不调用 provider，未匹配回合仍使用现有 provider 路径。
6. 保留并运行现有智汇 CLI、问题服务、协议、Gateway 进度和 Dashboard 确认卡测试。

## 非目标

- 不把“查询销量”解释为独立历史销量报表。
- 不自动执行生产导出，也不从聊天文本推断确认。
- 不引入新的 Desktop IPC、数据库表、凭据字段或第三方依赖。
- 不修改智汇接口参数、认证方式或请求频率。
