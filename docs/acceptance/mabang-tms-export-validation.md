## 使用和范围

桌面设置新增“马帮 TMS”，填写账号和密码即可，不设生产开关。配置 v10 迁移到 v11，密码使用现有加密存储；前端只显示是否配置。清除后不从环境恢复。开发环境可以在 `settings.json` 的 `integrations.mabangTms` 配置 `managed: true` 和 `account`，密码通过 `LXE_MABANG_TMS_PASSWORD` 注入；已保存密码优先。运行时注入 `LXE_MABANG_TMS_ACCOUNT` 与 `LXE_MABANG_TMS_PASSWORD`，不接受旧 ZHIHUI 环境别名。

唯一命令 `lxeskill mabang-tms products export` 支持 `--warehouse PH1|VN1|all`。Agent 未指定仓库时先询问，只有明确全部仓库才使用 `all`；Agent scope 环境下漏传仓库在登录前拒绝。无 scope 的外部 CLI 无参调用保留历史全仓兼容。沿用 `status=1`、`isConfirm=1`、`gridproperty=-1`、`if_produce="-1"`、`stockQuantity=-1` 等固定筛选，实际条件见结果 `filters`；`all` 不取消筛选。代码未定义这些枚举的完整业务含义，不保证覆盖全部商品或库存状态。12 个字段沿用 PR，包含 `sale5`，不猜其窗口。每次任务登录一次，Token 仅在内存复用。

按账号锁串行执行。每页最多请求 1000 条，按内部 ID 导出，立即下载、校验并保存原始批次。只有唯一 ID 总数等于接口总数且所有批次通过校验时成功；短页不会提前结束。最多 100 页、10 万条、15 分钟。仅列表查询允许有界重试，提交、下载和认证拒绝后不自动重试。

输出目录由 catalog 的 `mabang_tms_exports` 定义，按账号摘要和运行编号隔离。原始 XLS/XLSX 字节保留，本次各批按顺序追加为一份合并 XLSX，文本销量、重复 SKU、负库存和零价格保持不变。源表公式／错误单元格、异常表头及商品仓库覆盖不符时停止；同一 SKU 多行不自行去重或求和。合并是本地生成文件，不冒称平台原件。后续批次失败时只交付已校验部分，保留原始错误；发布失败不隐藏此前的导出失败。

## PR 前反方审查结论（2026-10-16）

审查复现同 SKU/同仓多个库存记录少导后仍成功的问题，已在原 Excel 覆盖检查增加计数下界：每组输出行数至少覆盖输入记录数，同时保留一 ID 多行。该检查仍不是逐 ID 或精确展开行数证明，无法识别条数相同的重复替代，同名仓库的文件身份也仍需真实证据。

早期审查把 `totalPage` 当成总页数并增加严格校验，该解释已被 2026-10-16 保存的 VN1 诊断响应推翻：记录在顶层 `datas`，总数在顶层 `totalNum=4208`，`pop` 内另有 `totalNum`、`pageSize=1000` 和 `totalPage`；五页的后者依次为 1、2、3、4、5，行数为 1000、1000、1000、1000、208。它在这组响应中表现为当前页回显，不能作为可靠总页数或结束依据，不推定其在所有响应中都有固定语义。

当前忽略 `totalPage` 的值和格式，缺失、`null` 或无关格式变化不据此阻断有效分页；不用它判断结束、请求预算、跨页稳定性或包装层相等。继续累积唯一顶层记录 ID，只有累计数达到稳定的 `totalNum` 且所有导出批次校验通过才成功；短页继续请求。显式 `page/pageNo/pageNum/currentPage` 若存在仍检查请求页，提前空页、页内/跨页重复 ID、总数变化和累计超总数仍拒绝；实际最多 100 页、10 万条、15 分钟独立保留。错误仍按原合同只交付此前通过校验的部分。

用户提供的浏览器请求为 `pageSize=50`；上述已保存的 CLI 诊断请求为 1000，本轮不改变原客户端页大小或请求参数。新增 [脱敏分页元数据 fixture](../../python/lxeskill_cli/tests/mabang_tms/fixtures/vn1-pagination-metadata.json) 仅保留已观察的字段与行数，商品、ID、Excel 均为离线合成。PH1/all 用相同结构做范围组合回归，不冒称已有两者完整逐页抓包；零值、大值、固定值及包装层不同值也仅为边界测试。
