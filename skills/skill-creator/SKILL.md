# 创建与修改用户技能

Skill 是给未来对话复用的工作指令及必要资源。用现有 read、write、edit、exec 工具编写文件，不需要新增工具或注册业务命令。

## 理解需求

从用户请求和当前对话确定用途、何时触发、输入、输出和关键步骤。信息充分就直接创建或修改；只追问影响结果且无法推断的缺失信息。保留真实方法，不把某次任务的订单号、临时路径、账户凭证和个人资料固化为默认值。

指令能解决时先写指令；重复计算或数据转换需要确定性时再添加脚本。只创建实际需要的 scripts/、references/、assets/，模板和素材放 assets/，长资料放 references/ 并说明何时读取。

## 保存位置

- 用户未指定位置：使用最新 environment_context 的 user_skills_root，保存到 `<user_skills_root>/<name>/SKILL.md`。这是运行时解析后的真实目录，不要猜测安装位置或使用当前工作目录下的 skills/。
- 用户指定其他位置：尊重该位置；只有保存到已知 Skill 来源内才会自动发现。普通目录中的输出说明“已保存，未加入自动发现”，不要自行登记目录。
- 修改前先读取目标文件，保留未要求改变的内容与启停配置。共享目录中的原件仅在用户明确要求时修改；不得把用户技能写入官方资源目录。

## 编写

新技能的 name 使用小写字母、数字和连字符，最多 64 字符，文件夹名与 name 一致；description 非空且最多 1024 字符，写清能力和触发场景。type 默认是 default。正文可以使用中文。

```markdown
---
name: weekly-report
description: 根据用户提供的工作记录整理中文周报，用于生成或修改周报。
type: default
---

根据工作记录整理完成事项、问题和下周计划。保留真实数据，缺失内容标注待补充；用户提供模板时沿用模板。
```

初始化器可创建所需资源目录，但不写占位 SKILL.md。先完成附属文件，再用 write 写入最终 SKILL.md。从本 Skill 的实际目录解析 scripts/ 路径，通过 exec 执行；开发环境使用 `uv run --frozen python`，安装版沿用受管 Python 执行能力，不安装新的依赖。

```text
python scripts/init_skill.py weekly-report --path <user_skills_root> --resources references,assets
python scripts/quick_validate.py <user_skills_root>/weekly-report
```

上面是脚本参数示意。exec.cwd 指向本 Skill 目录，参数包含空格时按当前平台正确引用；不要把示意路径原样执行。已存在技能不重新初始化。

组合官方能力时，按可用技能目录中的名称定位并读取对应 SKILL.md，使用其既有命令。不要假设官方技能与用户技能是相邻目录，也不要把已有业务命令复制成新技能的 commands 声明。

## 校验与交付

完成后运行 quick_validate.py；它只检查格式和引用，不会运行用户脚本。若校验失败，保留实际错误，修复后重试；不能把未通过校验的结果称为创建成功。修改已有共享技能时可用 `--compatibility` 检查加载兼容性，避免强制重命名旧技能。

新增或修改的脚本用真实格式的样例验证。格式检查通过不代表执行效果正确。需要外部写操作的验证遵循用户已有授权；未执行的验证如实说明。Skill 不能授予权限或改变命令所有权，紫鸟页面操作必须沿用官方配对的 Selenium 链路。

用户已明确要求创建或修改，就直接完成并告知名称、用途、实际文件位置、校验结果和一句使用示例。新建默认启用，修改保持原状态。新技能由运行时自动发现，下一轮对话可使用；不要声称点击技能就会独立执行脚本。
