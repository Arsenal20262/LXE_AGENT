# 雅仓数据导出

## 业务平台与仓库范围

雅仓 ERP 导出接口用于获取当前账号可见范围内的商品、库存和销量报表；相关业务涉及 Shopee 与 TikTok Shop，但这些不是 Shopee 或 TikTok Shop 的官方接口。四仓业务对应关系如下：

| 仓库 | 国家 | 涉及的销售平台业务 |
| --- | --- | --- |
| `MY8801` | 马来西亚 | Shopee |
| `PH8805` | 菲律宾 | Shopee |
| `TH8802` | 泰国 | TikTok Shop、Shopee |
| `VN8806` | 越南 | Shopee |

此映射只说明仓库级业务范围，不表示报表支持按销售平台筛选或分拆，也不表示每条商品记录都带有可验证的平台归属。当前雅仓 Skill 支持上表四仓；请求超出该 Skill 范围或数据来源不明确时，应说明当前范围并向用户确认，不在本 Skill 中指定其他 ERP 或 Skill。

## 接口与报表说明

雅仓 ERP 通过以下三个接口分别发起报表导出；实际执行仍通过现有导出 CLI：

| 报表 | 雅仓接口 | 报表主要内容 |
| --- | --- | --- |
| 库存动销 `inventory-sales` | `GET https://api-oms.seaya.cn/sys/customer/mrpPrepare/export` | SKU、商品名、仓库、3/7/15/30/60/90 天累计销量，以及库存、占用、在途、冻结、可用和缺货数量等字段。 |
| 当前库存 `inventory` | `GET https://api-oms.seaya.cn/sys/customer/stockWarehouse/export` | 条码、SKU、商品标签与规格、仓库、库存/占用/在途/冻结/可用数量、商品标题、图片和状态等当前库存信息。 |
| 仓库产品资料 `products` | `GET https://api-oms.seaya.cn/sys/customer/sku/export` | 条码、SKU、规格、中英文标题、长宽高、重量、图片链接和创建时间等产品资料；该报表是全局导出。 |

每个报表接口发起导出任务后，CLI 通过 `GET /sys/customer/downPath/list` 匹配本次任务，取得下载信息，再下载并校验 XLSX。接口返回或下载地址不是最终交付文件；只有 CLI 生成并校验后的本地 XLSX 才作为报表产物。

销量列是对应时间窗口的累计量，不是日均销量或逐日明细。库存字段沿用雅仓报表口径，不据字段名推导库存公式或字段间关系。仓库产品资料“创建时间”在已确认的越南备货流程中作为真实上架时间使用；其他业务不据此推断入库或上架时间。

接口地址仅用于解释报表来源与用途。实际执行必须使用 `lxeskill yacang reports export`，不得让 Agent 按接口地址自行发 HTTP 请求。

## 选择报表与范围

- 用户只说“导出雅仓数据”时，用已有 `ask_user_question` 询问需要哪类报表，可选一类、多类或全部。用户取消、跳过时停止，不默认全选。
- 按用户明确要求的数据分别选择报表：

  | 请求表达 | 导出报表 |
  | --- | --- |
  | 单独请求“销量”或“库存动销” | `inventory-sales` |
  | 单独请求“库存”“当前库存”或“库存列表” | `inventory` |
  | 同时请求“库存和销量”或“库存及销量” | `inventory-sales` + `inventory` |

  库存动销表虽然包含部分库存字段，也不能代替独立的当前库存报表；用户同时要求库存和销量时，必须分别导出两类报表。
- “仓库产品资料”选择 `products`。按平台默认产品状态导出，实际范围见结果 `filters`。原表包含创建时间，没有独立的入库时间列。越南备货业务已确认仓库产品的创建时间是真实上架时间；要求生成越南备货清单时使用 `vietnam-replenishment`。独立导出只交付原始字段，不推断入库时间。
- 未指定仓库默认全部四仓：`MY8801` 马来西亚、`PH8805` 菲律宾、`TH8802` 泰国、`VN8806` 越南。指定时仅选择对应仓库；不确定或范围矛盾时先问，不自行扩大。
- 仓库产品资料是一次全局导出，不能按仓筛选；用户明确限制它的仓库时，先确认是否接受全局文件。混合请求中的仓库范围只约束库存动销和当前库存。
- 库存动销未指定源表“创建日期”范围时省略 `--created-from` / `--created-to`，表示不限制；“7天销量”不是创建日期筛选，也不裁剪源表的其他累计字段。
- 库存动销的“创建日期”与仓库产品资料的“创建时间”是不同口径，同一 SKU 的值可不同。`--created-from` / `--created-to` 只筛选前者。越南备货的上架时间使用已确认的仓库产品创建时间；其他商品建档、入库等业务时间不能据此推断，不将两个字段混用。
- 库存动销下载并校验后直接去掉末列“创建日期”，只保存和交付处理后的文件；日期筛选仍作用于源表，实际筛选保留在结果中。当前库存列表原本没有该列，仓库产品资料的“创建时间”保留。不把交付的库存动销表称为逐字节原件。
- 历史库存、逐日销量、报表没有的销量窗口和不支持的筛选，先说明实际能力并询问可接受的替代范围，不静默替换。
- 只提 Shopee、未指定雅仓或国家/仓库时，不能仅凭 Shopee 选择雅仓；Shopee 覆盖多个国家，应先确认取数系统或范围。用户明确指定雅仓泰国 TikTok Shop 数据时，可选择 `TH8802`；用户仅提泰国 TikTok Shop、未指定 ERP，且上下文不能唯一确定来源时，应先确认取数系统。雅仓仍按仓库范围导出，不按销售平台筛选或拆分；`TH8802` 同时涉及 Shopee 与 TikTok Shop，交付时必须说明实际导出的是泰国仓范围报表，可能包含两个平台的数据，不能称为 TikTok 专属数据。若用户只接受 TikTok 数据，先说明该限制并询问是否接受仓库报表。

## 执行

作为完整越南备货任务的取数步骤时，导出 `inventory-sales`、`inventory`（仅 `VN8806`）及全局 `products`，不传 `--created-from` / `--created-to`。这是已确认的越南计算输入，无需再次询问报表选择或是否接受全局产品资料。成功后使用 `artifacts` 中的真实路径，按 `vietnam-replenishment` 继续独立计算；本导出命令不在内部启动计算。

账号手机号及密码在桌面“雅仓”设置中配置，不读取密码文件、不把凭据放进命令。通过 `exec` 调用唯一 CLI：

```text
lxeskill yacang reports export --report inventory-sales --warehouse MY8801
```

参数仅包含：
- `--report`：必填，可重复；从 `inventory-sales`、`inventory`、`products` 中选择。
- `--warehouse`：可重复的仓库编码，省略为四仓。单独导出全局产品资料时省略。
- `--created-from`、`--created-to`：仅在包含库存动销且用户明确筛选该表“创建日期”时同时提供 `YYYY-MM-DD`；不筛选仓库产品的“创建时间”。

三类全部请求使用 `--report inventory-sales --report inventory --report products`，最多九份交付文件。每仓每类一份，全局资料仅一份。脚本本次登录一次，Token 仅在进程内存中复用。只接受命令行选项，不使用 `--params`、`--input-json` 或 `--stdin-json`。

命令仍在运行时等待同一执行，不再次启动。平台提交后需要等待生成并下载文件，不能在开始轮询时就声称导出完成。

## 结果与交付

- 只读取最后一条 `type="result"` 的 `ok`、`data` 和 `files`。保留 `data.params`、`data.tasks`、`data.artifacts` 的真实范围、文件路径、工作表和行数；下载时间不等于平台数据更新时间。
- 用户以某个销售平台（如泰国 TikTok Shop）为目标请求雅仓导出，但实际交付的是仓库范围报表时，交付说明必须明确列出本次导出的报表类型、仓库及实际数据范围。对于泰国仓 `TH8802`，说明该仓涉及 Shopee 与 TikTok Shop，文件可能包含两个平台的业务数据，不代表仅包含 TikTok 商品。不得将仓库全量报表描述为 TikTok 或 Shopee 专属报表，也不得根据 SKU 或商品名称推断销售平台归属。
- 独立导出或数据准备任务，将 terminal `files` 一次交给 `send_files`。完整越南备货任务保留三份报表作为计算输入，计算成功后交付最终清单，不自动发送中间报表。发送成功才称已交付，发送失败只重试附件发送。
- `ok=false` 且 `data.status=partial_success` 时保留已成功文件，说明失败和未执行的仓库/报表及实际原因。独立导出或数据准备任务仍可交付 `files` 中的部分文件；完整越南任务缺输入时停止计算，不混用旧报表。不声称全部成功，不自动重跑整单。
- 零行明确说明该范围没有数据，不推断零备货需求。除库存动销去掉末列“创建日期”外，不合并、重写其他列或补列，不生成备货建议。
- 错误保留 `data.error`、任务内 `error` 及顶层 `error.message` 的实际脱敏诊断。`date_range_required` 时说明平台限制并询问库存动销表“创建日期”范围；不得自动退为当天。
- 登录、限流、网络、提交或队列状态不确定时报告失败和已完成阶段，不自行重试。用户要求再试时才调用；脚本会保留并核对未确认提交，不盲目重新创建任务。
- 不执行马帮的认证刷新，不输出 Token、验证码、密码或签名下载地址。
