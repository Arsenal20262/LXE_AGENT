# 东南亚备货流程与数据准备

## 入口与范围

- 用户只询问流程时解释当前能力，不执行采集。
- 用户明确要求查询越南备货、生成越南备货清单、出越南备货单、做越南补货建议，或问“越南这批该补多少”时，读取 `vietnam-replenishment` 并由它选择已有三份报表，或复用 `yacang-reports-export` 获取来源，再调用独立计算命令完成 VN8806 五表生成与交付。用户指定或上传本轮映射表时通过 `--sku-map-file` 使用真实文件路径；多文件无法确定时先确认。未指定文件则使用桌面保存的映射表。长期上传和替换请到「越南备货设置」。显式文件无效时不沿用旧表。只问流程、参数或文件内容时不生成。只说“看看越南库存”而无法判断要原始报表还是补货计算时先澄清；只要原始报表时走 `yacang-reports-export`。
- 用户要求准备其他东南亚备货数据时，完成下面的数据采集与交付。要求其他东南亚地区的完整备货时，先说明目前只能完成数据采集，再完成已授权的这一阶段；不把原始报表称为备货建议。
- 按用户明确的业务模块和已有上下文选择流程。只说“备货”且无法判断业务范围时，询问是 Amazon 还是东南亚，不凭国家名称推断所属模块。Amazon 备货使用 `replenishment-workflow-map`。
- 用户只要求上马导出或登录时，分别读取 `shangman-products-export` 或 `shangman-login`，不扩大为完整备货任务。

## 当前数据源与衔接

| 数据来源 | 用途 | 采集 Skill | 实际产出 | 后续使用 |
|---|---|---|---|---|
| 上马 ERP | 当前配置账号可见的商品、库存和销量数据 | `shangman-products-export` | 一份平台原始 XLSX，以及文件路径、工作表和数据行数 | 本入口交付采集结果；整理与备货计算尚未接通 |
| 马帮 TMS（旧称智汇 TMS） | 当前账号可见全部仓库的正常商品，全部库存状态 | `mabang-tms-products-export` | 一份按批次追加的合并 XLSX，保留同 SKU 多行 | 原始分批文件本地保留，不进行备货计算 |
| 马帮巴西海外仓 | 用户明确选择时采集库存动销及固定时间范围的调拨数据 | `mabang-brazil-reports-export` | 原始库存 XLSX 和调拨分批 XLS | 作为额外数据源交付；巴西不属于东南亚，不默认采集或计算 |
| 雅仓独立导出 | 所选仓库的库存动销、当前库存及全局仓库产品资料 | `yacang-reports-export` | 每仓每类一份原始 XLSX、文件路径、工作表和行数 | 可独立交付原始报表，也可将三份路径传给越南计算入口 |

越南备货的取数和计算分开调用：已有三份适用的原始报表时直接交给 `vietnam-replenishment`；需要采集时先读取 `yacang-reports-export`，导出 VN8806 库存动销、当前库存及全局产品资料，再将结果中的真实路径分别传入计算命令的 `--sales-file`、`--inventory-file`、`--products-file`，不添加创建日期筛选。计算命令不会自动采集；失败时保留已经完成的导出步骤，不能为了重试计算再次触发采集。其他数据准备先按用户明确的数据源选择采集 Skill；仅说“准备东南亚备货数据”且上下文无法确定来源时，询问上马、雅仓、马帮 TMS 或所需组合。不要默认同时导出多个平台，不跨来源合并报表。独立雅仓导出的数据类型、日期和仓库选择遵守 `yacang-reports-export`；其成功及部分成功文件都交回本入口统一交付，说明失败和未执行范围。

`shangman-login` 为上马数据采集提供认证支持；需要登录时由导出 Skill 衔接，成功后回到导出步骤。登录本身不产生业务数据。

1. 选择上马时读取 `shangman-products-export`，按其声明的 CLI 获取本轮原始报表。平台返回当前账号可见的全量数据，不承诺指定国家、店铺、仓库或日期的筛选；用户有筛选要求时遵守导出 Skill 的范围确认规则。
2. 上马已有有效登录态可以直接复用，不先重复登录。认证恢复、运行等待及错误处理都遵守对应 Skill，不套用马帮的 `lxeskill auth refresh`。
3. 接收最后一条 terminal 的 `ok`、`data` 和 `files`，保留实际文件路径、工作表、行数及本轮来源。不猜路径，不将导出时间声称为平台数据更新时间。
4. 上述通用数据准备流程到原始数据采集为止。由本入口调用一次 `send_files(paths=<terminal.files>)`，只交付所选数据源本轮 terminal.files 中的文件，并区分平台原始报表与马帮 TMS 合并表；导出步骤已经交付时不重复发送。越南五表成品由 `vietnam-replenishment` 自行交付，本入口不重复发送。

## 边界与完成标准

- 不调用 Amazon 的店铺解析、销量分析、深圳库存、未关联货件或备货计算技能处理上马、雅仓或马帮 TMS 报表。越南已有专用五表生成；其他东南亚来源尚无整理与计算步骤，不自行套用 Amazon 口径或编造算法补齐。
- 新增数据源或后续处理能力时，在本入口表中登记其用途、采集 Skill、产出及实际消费者；下载、认证和文件校验规则由对应 Skill 维护。只有已经接通的步骤才能执行，多个来源不得在缺少明确对应关系和使用规则时自行合并或互相替代。
- 通用数据准备成功后说明已完成“东南亚备货数据采集”，报告来源、文件和数据行数；零行时明确没有商品数据，不推断为零备货需求。其他地区的完整备货请求还需说明整理与计算尚未接通；越南生成成功按其专用 Skill 只交付最终 XLSX。
- 文件发送成功才称已交付；发送失败只重试交付。业务失败保留实际脱敏诊断及已完成阶段，恢复遵守对应 Skill，不擅自重复导出、不宣称整轮备货完成。

马帮 TMS 按 `mabang-tms-products-export` 的固定范围执行，与马帮 ERP 独立。成功或部分成功结果交回本入口统一交付，不再次发送，不自行按 SKU 合并销量。

用户明确要求巴西数据时读取 `mabang-brazil-reports-export`，遵守其报表选择、时间范围和认证规则；成功或部分成功文件交回入口统一发送。不要对巴西数据执行 Amazon 店铺解析或计算，也不跨来源合并。
