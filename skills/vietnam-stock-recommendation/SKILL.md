# 越南备货清单

## 入口边界

- 先判断目标：只要雅仓原始报表交给 `yacang-export`；明确使用已有三份雅仓 XLSX 生成越南备货，走下述离线入口；其余明确请求本轮备货结果，走在线 `recommend`。不要因为看到三个文件就自行推断是三报表，也不要因为看到一个文件就根据文件名猜它是 SKU 参数表。用户仅说“看看越南库存”等无法确定目标时先澄清。离线结果只能称为“基于用户提供的已有报表生成”，不声称这些报表来自同一次导出或代表今天的实时数据。
- 在线与 SKU 绑定场景识别三种请求：只绑定新版越南 SKU 参数表、只用已绑定表生成备货清单、用新上传表先绑定再生成。每条新上传唯一 `.xlsx` 的用户消息都是新的处理请求，即使文件内容与更早上传相同。只按当前消息及合规紧邻消息的附件和本轮工具结果决定动作；不从长对话历史推断这份新附件已经绑定，也不因上轮取消、中断或同名文件而停在状态推测中。用户明确要求查询或生成越南备货清单时，如果本条恰好只有一个附件，且该附件为 `.xlsx`，或者紧邻上一条用户消息有符合下条条件的唯一 `.xlsx` 附件，即使没有说“绑定”，也先绑定该附件，成功后再生成；“查询”仅指请求本轮备货结果，不包括询问功能或流程。仅上传一份 `.xlsx`（或只说明这是 SKU 表）但未明确要求绑定或查询时，不调用绑定或生成；在 Desktop 用已有的 `ask_user_question` 弹出“仅绑定 / 绑定并查询”两个单选项，等待用户选择。用户随后在聊天中紧邻回复时按确认/继续处理规则使用该附件。SKU 绑定路径遇到多附件必须先确认要使用哪一个，包括其中只有一份 `.xlsx` 的情况；确认前不凭文件名或其他线索自行选择，也不开始生成。明确三报表离线请求按下面的完整集合规则处理，不逐份选择或绑定 SKU 表。
- “帮我出一份越南备货单”“按越南库存和销量算要补多少”“做越南补货建议或备货计划”“重新生成越南备货清单”“查本轮越南备货量”均属于上述查询或生成请求，按相同附件与绑定顺序执行。只说“看看越南库存”而无法判断要原始报表还是补货计算时先澄清，不凭附件文件名推断用途。只问流程、所需资料或历史文件时先回答或澄清，不执行绑定或生成；只问当前 SKU 表绑定状态或版本时不执行绑定或生成，提示在工作台刷新 SKU 卡查看当前版，以及存在时显示的上一版，不猜状态。
- 运营口语同样按意图处理：“越南这批该补多少？”“帮我出张越南备货表”，以及“我刚传了越南 SKU 表，想按现在库存和销量看下哪些货要补、各补多少，出份表给我”都要求本轮结果；后一句若有合规新附件，先绑定成功再生成。“这版越南 SKU 表先替换进去，暂时不用算”只要求绑定，成功后停止。口语中的“这版”“刚传了”不能放宽下述附件来源规则；没有当前或符合条件的紧邻附件时，不搜索旧附件。“看看越南仓还有多少货”仍可能只要原始库存，先澄清；“导出越南仓库存原表”只走 `yacang-export`；“这个 Excel 帮我看看”仅有附件且用途不明时先问用途。
- 需要绑定时，当前消息恰好只有一个附件，且它是 `.xlsx` `local_file`，就让宿主自动选取该附件；文件内容是否为越南 SKU 表由绑定命令校验，不凭文件名猜测。当前消息没有附件时，仅当紧邻上一条用户消息刚上传了可唯一确定的 `.xlsx` 附件、当前消息明确属于确认、澄清或继续处理该附件（包括要求“查询越南备货”）、期间没有新候选，才允许使用那个紧邻附件；不要求先询问用途。当前或合规紧邻附件与明确查询/继续处理请求一起出现时，本轮调用一次绑定；绑定返回 `unchanged` 也视为本轮绑定成功，不根据旧对话里的版本号、绑定结果或中断状态跳过这一步。若本轮已经收到该附件绑定成功的工具结果，直接继续生成，不重复调用绑定。若上一条有多个附件，当前消息还必须明确选定其中一份 `.xlsx`；仍无法唯一确定时要求重新上传单一附件。不跨多轮复用历史附件，不从更早消息搜索旧附件，也不根据“之前上传过”猜测附件来源；明确要求绑定但没有可选附件时提示上传本轮附件。本轮提供非 `.xlsx` 附件时拒绝绑定，不改用旧 current 生成。宿主会核验会话附件记录、消息时序和实际 XLSX 文件；当前或紧邻消息只有一个合规候选时，宿主自动选取附件，不需要你查找附件 ID。你仍须先判断确认/澄清/继续处理的语义，多附件在用户确认前不得选择。
- 离线生成只接受用户明确要求“用已有三份报表生成”且当前消息有完整三份 `.xlsx` `local_file`，或当前消息无附件、紧邻上一条用户消息刚上传完整三份且本条明确继续处理它们。例如“用已有雅仓报表生成越南备货”在满足三份报表条件时选择 `vietnam stock generate`，不得调用在线 `vietnam stock recommend`。多附件集合必须来自同一上传轮次，不能从更早消息搜索、跨轮凑齐或按文件名猜测报表类型；当前消息有附件但数量不是三份时，不回退旧附件。只有三份报表用途不明时先澄清；少于或多于三份、混入非 `.xlsx` 时提示重新上传正确的完整集合。宿主负责受控附件数量和来源核验；Vietnam 命令再次校验内容、报表类型及仓库约束。离线使用已绑定的 SKU current，不绑定报表中的任何文件为 SKU 表；缺少有效 current 则失败并提示先绑定 SKU 表。Desktop 的受控工具只收 catalog 命令 ID，不把聊天里写出的文件路径传给工具；直接 CLI 才能接收三条显式来源路径。
- 运营在聊天中附上 `.xlsx` 越南 SKU 参数表并说明是越南备货输入时可以只绑定；同时要求查询或生成时先绑定再生成。五表骨架已随应用内置，不要求上传完整备货清单模板。工作台只显示 SKU 表当前版、上一版和回滚状态，不在工作台上传。
- 在线 `recommend` 会先校验 `vietnam_sku_parameter_map` 的 current，再获取同一轮雅仓库存动销、当前库存列表和全局仓库产品资料，最后生成并校验五表 XLSX；没有 current 时在调用雅仓前停止。离线 `generate` 先本地校验用户提供的三份报表，再复用相同的受信 current、Workbook、Office 重算和结果校验，全程不调用雅仓。不得把任意路径、旧版映射表或历史模板传给在线命令，也不得从历史文件猜成本、跨境价或折扣价。
- 当前映射表须存在、有效且至少含一个 SKU，但可以没有本次来源中的某些 SKU 行；已有行的成本、跨境价、折扣价也可分别为空。生成成功时，本次来源 SKU 仍全部进入最终五表工作簿的主表与三张来源表：缺映射行的热销、成本、价格、备货天数、备货量和财务结果留空；已有行的空热销默认 `2`，空价格只让依赖它的财务结果留空。显式 `0` 不视作空白。不要因这些允许的空值拒绝交付，也不要猜测缺失 SKU 的数量或价格。
- 本业务已确认仓库产品的“创建时间”是真实上架时间；总在途取本轮当前库存列表的“在途数量”。这些口径由命令校验和写入，不手工替换来源。
- 本次生成使用 Desktop 保存的长期四参数；运行环境中四项均缺席时才使用系统默认值 `0.8 / 0.8 / 0 / 3900`。命令结果中的 `data.config` 给出本轮生效值，`data.config_source` 只标记可观测来源 `environment` 或 `default`，不得把任意环境注入值称为已保存的 Desktop 设置。若用户明确指定本次使用其他值，先说明聊天临时覆盖暂未支持，并停止本次生成；不要默默忽略要求后按长期值或默认值运行。
- 用户只要雅仓原始报表时转 `yacang-export`，不要启动备货生成；用户明确用已有三份报表时不重新导出雅仓。不要用该导出 Skill 的原始文件代替最终备货清单。

## 执行

桌面会话使用 `managed_lxeskill`，不能改用通用命令执行入口或要求 Full access。受控工具不可用时如实报告环境问题，不搜索历史文件，也不改用旧路径。工具只接受 catalog 命令 ID；仅在单附件绑定且已明确选定文件时，才可传宿主能够核验的 `attachment_id`。不能传 shell、文件路径、cwd、环境变量或额外参数。唯一合规 XLSX 加明确在线生成要求时，直接绑定再生成，不另行请求点击确认。不要为取得附件 ID 搜索目录、读取会话记录或读取 XLSX；宿主会自动选取唯一候选。离线命令的完整三附件集合由宿主按 catalog 受控选择，无须模型逐份传 ID 或路径。

**只有裸上传一份已识别的越南 SKU 表、未说明要绑定还是生成时**，将 `ask_user_question` 作为本步唯一工具调用，参数为：

```json
{"questions":[{"id":"vietnam_sku_action","question":"这份越南 SKU 表要仅绑定，还是绑定并查询越南备货？","options":[{"label":"仅绑定"},{"label":"绑定并查询"}]}]}
```

等待工具回答；选择“仅绑定”只绑定，选择“绑定并查询”则绑定成功后生成。表单答案在当前轮可继续处理当前附件；若用户改为下一条聊天消息回答，按紧邻附件规则处理。同一用户消息对应的当前轮最多调用一次 `ask_user_question`。跳过、取消、答案不明确或工具不可用时不绑定、不生成，说明需要明确选择；不要把跳过当作默认同意。取消或中断只终止当轮处理；上一轮被取消或中断，不阻止本轮重新弹出选择框，也不能当作本轮已选择。当前消息已经明确要求绑定或查询时不弹此表单，直接按下面顺序执行。

按上述规则需要绑定时（包括查询或生成越南备货清单且本条恰好只有一个附件且为 XLSX，或确认紧邻上一条的唯一 XLSX），唯一候选直接调用一次：

```json
{"command_id":"vietnam_replenishment_bind_sku"}
```

等待这次 `managed_lxeskill` 调用完成，不另起命令。宿主从当前或合规紧邻消息自动选取唯一附件，核验存储记录并构造固定 CLI 参数。多附件仍需先请用户明确选定；只有可直接取得选定附件的 `attachment_id` 时才传该字段，不能取得时请用户单独重新上传选定的 XLSX，不搜索会话记录或猜测。读取工具返回的 terminal，检查 `ok=true`、`data.success=true`、`data.status` 为 `installed` 或 `unchanged`、`data.manifest_revision` 存在，且 `files=[]`。只有全部满足才说已绑定；`installed` 表示保存了新版，`unchanged` 表示内容未变、沿用当前版。只要求绑定时到此结束，不调用雅仓或 `send_files`。若同一请求还要求查询或生成，确认绑定成功后继续执行一次下方命令；绑定失败或结果契约异常时停止，不生成、不发送文件。绑定失败时不得沿用旧 current 生成。出错时转述 terminal `data.error.message` 或 `error.message` 的实际脱敏诊断，不自动重试或改用其他文件。

只有用户明确要求查询或生成在线备货时才调用在线生成命令：本轮有合规新附件则先等本轮绑定成功；本轮没有合规新附件则直接用受信 current 生成一次，由命令校验 current，缺少时如实提示上传并绑定 SKU 表。不从更早消息取附件，不推测历史绑定是否完成，也不为检查状态反复调用工具。SKU 绑定路径中多附件未确认、非 `.xlsx` 附件或绑定失败时不进入在线生成。只调用一次无附件参数的 `managed_lxeskill`：

```json
{"command_id":"vietnam_replenishment_generate"}
```

等待同一次调用完成，不另起新命令。只读取工具返回的 terminal，先看 `ok`，再看 `data.success`、`data.output_xlsx`、`data.error` 和 `files`。在线生成命令不接受 `attachment_id`、临时参数或映射表路径。成功后的 terminal 文件信息只供下一步校验；工具本身不发送文件。

用户明确要求使用已有三份雅仓报表生成，且附件满足上述完整集合条件时，只调用一次离线 `managed_lxeskill`：

```json
{"command_id":"vietnam_replenishment_generate_offline"}
```

这三份文件由宿主从当前消息或符合条件的紧邻上一条消息整组传入 `source_xlsx`；不要自行认领库存动销、库存列表、仓库产品的文件名，不调用 `vietnam_replenishment_bind_sku` 或在线 `vietnam_replenishment_generate`。命令在业务层再次校验恰好三份、XLSX 结构、三种来源各一份及 VN8806 仓库约束，后续步骤由同一确定性 Workflow 完成。无有效 SKU current、文件校验失败、Office 或结果校验失败时立即停止，不调用雅仓、不回退 `recommend`、不交付部分文件。读取 terminal 的 `ok`、`data.success`、`data.output_xlsx`、`data.error` 和 `files`，按下述相同的最终文件契约交付。

## 结果与交付

- 在线或离线生成的 `ok=false` 或 `data.success=false` 时不发送文件。若 `data.error.code=sku_parameter_map_required`，明确提示先在聊天中上传并绑定越南 SKU 参数表；无有效 SKU、坏表、非法数值、必要来源缺失或重算失败等其他失败，转述 `data.error.message` 或 terminal `error.message` 的实际脱敏诊断。离线失败时绝不调用雅仓补救或回退在线；两条路径都不自动重试整轮，也不改用旧文件或历史模板。
- 仅当生成的 `ok=true`、`data.success=true`、`data.output_xlsx` 存在，且 terminal `files` 恰好包含该最终 XLSX 时，调用一次 `send_files(paths=<terminal.files>)`。文件集合不符合条件时停止并报告结果契约异常；不猜文件路径，不发送雅仓原始报表、映射表快照或中间工作簿。
- 附件发送成功后再说已交付，可简要说明本次来源 SKU 数和 `data.config` 的生效值及 `data.config_source` 来源。在线结果来自本轮雅仓，离线结果基于用户提供的已有报表；离线时不得说“今天实时数据”或“同一次导出”。terminal 没有缺映射 SKU 计数时，不推断或声称具体缺失数量。若 `send_files` 失败，只用同一份 terminal `files` 重试附件发送，不重新运行生成命令。
